---
title: 快速开始
description: 在本地运行 Eveland，并部署第一个 Eve 项目。
---

本指南让 Postgres 运行在 Docker 中，四个 Eveland 应用在宿主机原生运行。这是在 macOS 或 Linux 上进行开发的最快路径。

## 前置条件

- Node.js 24 或更高版本
- 已启用 pnpm 的 Corepack
- Docker 与 Compose
- 本地 Eve 项目、Git URL 或 Zip 压缩包

## 安装并启动

```bash
git clone https://github.com/evelandhq/eveland.git
cd eveland
pnpm install

docker compose up -d postgres
pnpm --filter @eveland/api db:migrate

pnpm --filter @eveland/api dev
pnpm --filter @eveland/gateway dev
pnpm --filter @eveland/web dev
pnpm --filter @eveland/worker dev
```

打开 [http://localhost:3000](http://localhost:3000)。四个应用都不可缺少：Web 提供控制台，API 保存控制面状态，Worker 执行导入、构建和部署任务，Gateway 路由 Playground 与公开 Agent 流量。

> 开发时只选择一种模式：要么整个 Stack 都运行在 Compose 中，要么只有 Postgres 使用 Compose、其余应用原生运行。在同一个挂载工作区之间切换可能替换不同平台构建的 `node_modules`。

## 导入项目

1. 打开 **Projects**，选择 **New project**。
2. 导入 Git 仓库或上传 Zip 文件。
3. 等待源码校验完成。
4. 添加 Agent 所需的环境变量与 Provider Key。
5. 选择 **Build & Deploy**。

如果某些值由运维方持有、需要跨 Project 复用或只绑定到单个 Deployment，管理员可以在 **Settings → Secret profiles** 创建带 revision 的加密 Profile，再到 Project 的 **Secrets** 页面显式绑定。Runtime Profile 变更会排定向重启；Agent Connection reference 会在每次请求时解析当前值。浏览器永远不会收到 Value。

首次成功部署会创建不可变 Release 和 Preview Deployment。打开 **Playground**，通过 Gateway 开始一段全新的连续对话。界面会流式展示消息、实时 thinking、tool 调用和结果，支持确认、选项、文本及外部授权提示，并可上传最多 4 个图片、PDF、文本或代码文件。刷新页面会开始新对话；产生的平台 Session 仍可在 **Sessions** 中查看。

## 配置受保护的 Agent

打开 **Playground → Connection**，显式选择 Eveland 调用 Agent Eve route 的方式。可选 Local development、无凭证、HTTP Basic、Bearer、Vercel OIDC、custom headers 与通用 OIDC Authorization Code；Eveland 不会根据 Agent 源码或认证 challenge 自动猜测。Vercel OIDC 镜像已验证的 Eve 0.24.6/0.25.1 行为，同时把短期 token 作为 Bearer 与 trusted deployment header 发送。

配置 OIDC：

1. 在 IdP 中把 `<Web origin>/agent-auth/oidc/callback` 注册为精确 redirect URI。
2. confidential client 先创建保存 client secret 的 Project Secret，或绑定 `agent-connection` Platform Secret Profile，再在 Connection 中选择该引用；public client 选择 `none`，不需要 Secret。
3. 配置 issuer、client id、scopes、可选 audience 与参数模式、token endpoint authentication、可选 authorization parameters，以及 Eve JWT 或 UserInfo verification。
4. 保存 Connection，然后点击 **Authorize with identity provider**，或直接发送第一条 Playground 消息。

每位 Eveland member 都使用隔离的授权凭证。跳转期间第一条消息只保存在当前 browser session，callback 完成后仅发送一次。access/refresh token 始终加密保存在 API，不会返回 Web。

## 验证工作区

提交更改前，运行仓库使用的相同检查：

```bash
pnpm test
pnpm typecheck
```

继续阅读[部署 Eve 项目](/zh/docs/deploy)，了解 Preview、提升、回滚与稳定路由如何工作。
