Eveland 将编写的代码、构建产物、运行进程和公开流量分开。正是这种分离让 Preview 与安全提升成为可能。

## Project 生命周期

```text
Project
  └─ Source Revision        Git commit 或 Zip 快照
       └─ Release           不可变构建产物
            └─ Deployment  运行中的 Docker 容器或 systemd unit
                 └─ Route  稳定、预览或命名 Host
```

### Source Revision

Source Revision 是一次构建的精确输入。Git 导入保存拉取到的 Revision；Zip 导入保存上传快照。Eveland 注入运行时集成代码时不会修改导入源码，而是修改准备好的 Release 目录。

### Release 与 Deployment

Release 是不可变的构建 Artifact。Deployment 是这个 Release 的一个运行实例。再次构建会创建新的 Release 和 Deployment，而不是修改当前生产进程。

每个 Deployment 都记录自己的 runtime kind。生命周期操作根据这个已记录的所有者执行，因此 Docker Deployment 由 Docker 停止，systemd Deployment 由 systemd 停止。

## 路由与流量

- **Preview Route** 固定属于一个不可变 Deployment。
- **Stable Route** 可变，代表 Project 的生产入口。
- **Named Route** 可以提供另一个有明确含义的别名。

一条 Route 可以选择一个 Deployment，也可以将新 Session 分配到两个 Deployment。权重使用 10,000 个基点，合计必须为 10,000。

## Session 亲和性

新流量会被确定性分配。当 Eve 返回 `sessionId` 后，Eveland 会保存 Session 与 Deployment 之间的 `SessionBinding`。即使发生提升、回滚或某个流量权重降为零，后续消息仍会回到原 Deployment。

这也是 Deployment 可能进入 **draining** 而不是立即停止的原因：它可能仍拥有尚未结束的 Session。

## Session 与用量

Observer 独立于 Playground 记录 Session。因此，直接 Agent 请求、Schedule 和子 Session 都可以出现在统一的 Session 历史中。

Token 统计使用 Eve 报告的 `step.completed.data.usage`：

- Input 与 Output tokens
- Cache read 与 Cache write tokens
- Provider 或 Gateway 返回的成本（如果存在）

Provider 没有报告的用量会被标记为缺失，而不是估算。用量归属于真正消耗它的 Eve Agent 或 Subagent。
