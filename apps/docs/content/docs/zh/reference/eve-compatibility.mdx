title: Eve 兼容性
description: 理解 Eveland 已验证的 Eve 版本窗口与 Fail-closed Policy。
---

在 Eve 发布稳定 Compatibility Contract 之前，Eveland 支持最近三个经过完整验证的 Eve Minor Line。当前代码中的产品契约支持 `0.25.x`、`0.26.x` 与 `0.27.x`，验证版本为 `0.25.3`、`0.26.2` 与 `0.27.8`。

UI 仅将最新支持线 `0.27.x` 标为绿色。较旧但仍受支持的版本保持可运行，不过会以红色显示并提醒升级；不受支持的版本同样显示为红色且继续阻断。

Eve 0.27 将 Nuxt 部署迁移到 Vercel 稳定 Services Model，改善 Compaction 与 Prompt Cache，并让 Route Auth 返回符合标准的 Challenge。HTTP Basic 现在声明 Realm 与 UTF-8 Charset，并在 Unicode NFC 规范化后比较 Credential。Eveland 不通过 Eve 的 Nuxt Integration 托管导入的 Agent，也不会根据 401 Challenge 推断 Connection Method，因此不需要新增 Adapter 分支。

0.27.1–0.27.3 Patch 改善了 Workflow 并发与取消、队列化 Channel Delivery、Slack/Teams Routing、带 Prefix 的 Callback Route、Dynamic Tool 刷新、Sandbox Seed 写入顺序和 Diagnostic。Eve 0.27.2 还会在打开 NDJSON Stream 时先发送一个空白字节，并允许 Client Caller 显式关闭自动 Stream Reconnect。Eveland 的 Stream Monitor 已忽略空行，Gateway 会无缓冲透传该字节，Playground 则保留默认的 Durable Reconnect 行为。

Eve 0.27.4 新增通过 `POST /eve/v1/session/reset` 执行的 Durable Session Reset。Eveland 将最新 continuation token 保存在 SessionBinding 中，因此即使发生 Promote、Rollback 或 Weight 变化，按 token 恢复和 reset 仍会发送到拥有该 Durable Workflow 的 Deployment。Reset 成功后只清除 token 绑定；历史 Session → Deployment 绑定继续用于 Stream、观测与 Retention。迁移 `0029_sparkling_hammerhead` 会先回填已知 token，再创建唯一 Routing Index。

Eve 0.27.6 新增 Remote Agent 的显式 Principal Metadata Forwarding、忽略空的 Remote `outputSchema`，并修复 Base Path 下的 Remote Create/Cancel URL。Forwarding 默认关闭：发送端必须设置 `forwardPrincipal: true`，接收 Agent 必须定义精确的 `trustedForwarders` Predicate。Eveland 只透明代理 Body 和 Agent 自有认证，不会替 Agent 开启信任、重写 Principal 或转发 Credential。除此之外，经验证窗口内的 canonical create/continue/cancel/stream Message、Vercel OIDC Header、Eve Hook Event、Schedule 定义和 `SandboxBackend` 契约保持兼容。

Eve 0.27.7 新增通过 `session.stream({ follow: false })` 执行的有界 Catch-up Read。Client 会请求 `includeTailIndex=1`，Eve Route 返回 `x-eve-stream-tail-index`，读取到打开 Stream 时观测到的 Durable Tail 后即结束。Eveland 在公开路径与 Playground 路径中都原样保留该 Query、响应 Header 和无缓冲 NDJSON Body。有界读取要求 Client 与 Agent 均使用 Eve 0.27.7 或更高版本；旧 Agent 不返回 Tail Header，新 Client 会明确失败，而不是静默地永久 Follow。现有 Playground 继续采用默认 Live Follow。该 Patch 还会解析 Provider-executed Tool 的 Raw JSON String 参数，并把无法解析的参数转换成 Failed Tool Result，而不是让整个 Turn 失败；Eveland 私有 Telemetry Hook 继续接收正常的后续 Event Flow。单次 Nitro Build 优化只影响 Eve 的 Vercel Output，不改变 Eveland 的 Standalone Release Build。

Eve 0.27.8 新增 Authoring-time 的 `eve add` 与 `eve registry` 命令。Eveland 在 Import 或 Deployment 中不会运行这些命令，因此它们不会修改已导入的 Source Snapshot，也不会为 Release 增加额外 Network、Filesystem 或 Sandbox 权限。

即使 `^0.27.0` 等 Range 已允许新 Patch，Agent 项目也应刷新 Lockfile 并重新部署，才能实际获得 `0.27.8`。Eve 0.27.3+ 要求 AI SDK `ai@^7.0.34`；若项目单独钉死或锁定了更旧的 AI SDK，应一并升级。自定义 NDJSON Consumer 必须忽略空行；如果 Relay/Proxy 自己管理恢复，可以使用 Reconnect Opt-out，并且只有当目标 Agent 也使用 Eve 0.27.7+ 时才使用 `follow: false`；普通 Agent Client 应保留默认 Live Follow。只有在两端 Deployment 都升级、且接收端能精确识别可信 Forwarder 后，才应启用 Remote Principal Forwarding。

仅有 npm Publication 不会扩大窗口。新 Minor 只有在 Changelog/Source Review 与完整 Compatibility Matrix 通过后才进入；进入时会有意识地移除较旧 Minor。

## Enforcement Point

依赖缺失、超出窗口或无法证明兼容时，Eveland 会在以下位置 Fail Closed：

- Source Import 与 Preflight
- Build 与 Restart
- Cold Activation
- Playground Traffic
- Public Session Create、Continue、Cancel 与 Stream
- Public Session Reset
- Schedule Execution

Diagnostic 会要求项目 Owner Upgrade，而不是猜测旧 Protocol。生产环境升级 Eve 或 Eveland 前都应阅读 Release Note。
