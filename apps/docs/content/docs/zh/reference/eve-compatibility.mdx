---
title: Eve 兼容性
description: 理解 Eveland 已验证的 Eve 版本窗口与 Fail-closed Policy。
---

在 Eve 发布稳定 Compatibility Contract 之前，Eveland 只支持通过完整兼容矩阵的 Minor Line，并显式变更该窗口。代码中的产品契约支持 `0.37.x` 与 `0.38.x`，验证版本为 `0.37.1` 与 `0.38.3`。Eve 0.34–0.36 不再允许 Import、Build、Restart、Activation、Playground、Gateway 或 Schedule Execution。

UI 仅将最新支持线 `0.38.x` 标为绿色。Eve 0.37.x 保持可运行，不过会以红色显示并提醒升级；不受支持的版本同样显示为红色且继续阻断。

窗口此前依赖 Eve 0.27 的能力现在都是基线：通过 `POST /eve/v1/session/reset` 的 Durable Session Reset、通过 `session.stream({ follow: false })` 与 `x-eve-stream-tail-index` Header 的有界 Catch-up Read、符合标准的 Route Auth Challenge，以及默认关闭的 Remote Principal Forwarding。Eveland 在公开路径与 Playground 路径都原样保留这些 Query、Header 与无缓冲 NDJSON Body，且从不替 Agent 开启信任、重写 Principal 或转发 Credential。Eve 0.27.3 及以后要求 AI SDK `ai@^7.0.34`，若项目单独钉死了更旧的 AI SDK，应一并升级。

Eve 0.30 的行为同样已成为窗口基线：`localDev()` 改为看进程而非请求 Host，在 `eve start` 下不再放行任何请求——Eveland 上的 Agent 必须改用 `evelandIdentity()`、`httpBasic()` 或 OIDC，需要改什么见[将 Agent 迁移到 Eve 0.30](/docs/agents/migrate-eve-0-30)。Durable Cancellation Hook 现在是命令收件箱 `eve:session:{sessionId}:inbox`；手工 resume 旧 `{sessionId}:cancel` token 的 Agent 代码会**静默失效**。走 HTTP `POST /eve/v1/session/:id/cancel` 的不受影响——该 Route 与响应 Schema 均未变，Eveland 自己用的就是它。

Eve 0.31 的行为同样已成为窗口基线：Session 只按固定 ID 寻址——Session 只按 ID 寻址，TypeScript Client 用 `client.sessions.create(input)` 与 `client.sessions.attach(sessionId)`，Channel Route 拿到 `from(address)`、`to(channel, target)` 与 `attachSession(sessionId)`，Schedule Handler 用 `to(channel, target).send(message, { auth })`。Clear、Compact 与 Reset 位于 `POST /eve/v1/session/:sessionId/{clear,compact,reset}`。已接受的异步操作回答 HTTP `202`；对非活跃 Session 的后续请求回答 HTTP `409` 与 `code: "session_not_active"`。

Eve 0.32 的 Sandbox 契约是整个窗口的基线：自定义 Sandbox Backend Handle 必须实现 `stop()`。只实现了 `captureState()` 与 `shutdown()` 的 Backend 在旧类型下仍能编译，但当 Hook、Tool 或 Channel Callback 第一次调用 `ctx.getSandbox().stop()` 时会在运行期抛错。与 `shutdown()` 不同，`stop()` 必须保留 Durable Session，让之后的 Callback 能重新打开它。Eveland 自己的 `@evelandhq/sandbox-bwrap` 从 `0.1.1` 起已实现。Eve 0.32 还把 Tool Approval 的否定响应从 `deny` 改名为 `cancel`，并把交互式 Connection 授权回调绑定到具体的 Attempt（`/eve/v1/connections/:name/callback/:attemptId/:token`）。

**Eve 0.33 把 Channel 消息发送的默认策略改成了 `turnPolicy: "steer"`。** 在有 Turn 正在运行时到达的消息，现在会取消并替换该 Turn，而不再等它跑完。在 Channel 上或单次发送上设置 `turnPolicy: "queue"` 可保持原有行为——Eveland 注入的 Scheduler Adapter 正是这么做的，因此 Schedule 不会抢占用户正在等待的 Turn。Eve 0.33 还移除了 Dynamic Model 与 Dynamic Subagent 的编译期 fallback：`defineDynamic` 只接受 `events`，Dynamic Model Handler 必须返回具体选择，Dynamic Subagent 必须指定静态 Model。配置的 Model id 也从 `session.started` 的 Runtime Identity 移到了每个 `step.started` 事件上。

**Eve 0.34 默认会把 Human-in-the-loop 提问贴进 GitHub 讨论串。** 使用 `githubChannel` 的 Agent 现在会把待回答的 Input Request 写成 Issue 或 Pull Request 评论，供人在那里直接回答；不需要额外改动，但这些评论是新出现且对外可见的。Eve 0.34 还允许 Tool 或 Connection 把 `approval` 声明为 `{ request, response }` 而不只是一个函数——Response Policy 可以校验回应者身份并返回带标签的允许或拒绝决定——原有的函数简写继续有效。实验性的 `agent/instrumentation/` Provider 目录随 `experimental.instrumentationProviders` 开关提供；它与单文件 `agent/instrumentation.ts` **互斥**，开启其一会让另一种布局变成构建错误。`defineInstrumentation` 不再在 `tsc` 阶段拒绝未知键，拼错的选项要到 `eve build` 才会暴露。

**Eve 0.35 将 Instrumentation 内容改为显式 Opt-in，并引入带 Role 的 Instruction。** Eve 自身的 Instrumentation 只有启用 `recordInputs`/`recordOutputs`（或为本地 Trace 设置 `EVE_TRACES_CONTENT=on`）才记录 Model/Tool 输入输出。Eveland 注入的私有 Observer 不依赖该开关，仍按 Project 的 Eveland Capture Policy 工作。Instruction Module 现在使用 `content` 和可选的 `system`/`user` Role；旧 `markdown` 已弃用，user-role Instruction 会进入 Durable Model History。Session/Turn Start Event 还可能携带可选的 Portable Trace Context。当前支持的 Build 都产生 Discovery Manifest v13；Projector 仍接受 v12，以读取不可变的历史 Artifact。

**Eve 0.36 将默认模型改为 `zai/glm-5.2`。** 依赖 Eve 隐式默认值的项目重新构建后，Provider、行为、Credential 要求与费用都可能变化；升级前应显式固定 `model`。`eve/sveltekit` 也迁移到稳定的 Vercel Services Model，并移除 `configureVercelJson`、`servicePrefix` 与 `EVE_SVELTEKIT_SERVICE_PREFIX`；使用这些选项的项目必须先迁移源码。

**Eve 0.37 增加 Vercel Sandbox Drives，并调整本地创作 CLI。** Eveland 仍会用受管 bwrap backend 替换项目声明的 Sandbox Backend，因此 Eveland Deployment 不暴露 Vercel Drive Mount。生成的 Definition 会保留 authored `bootstrap()`、`onSession()`、`description`、`revalidationKey` 与 Workspace Seed；只有 `backend` 归平台所有。`eve init`/`eve dev` 的变化只影响本地创作，不改变平台明确执行的 Build/Start 命令。

**Eve 0.37.1 增加 Durable Background Work 与 Invocation Channel。** 当 `subagent.completed` 携带 `backgroundTask: { status: "working" }` 时，它只是后台任务回执，不是 Child 的终态；Consumer 必须继续跟随 Child Stream。Remote Child Stream 可以经 Parent 的 `GET /eve/v1/session/:parentSessionId/subagents/:callId/:childSessionId/stream` 路由读取。已认证 Caller 可用 `operationId` 实现 Session Create-once；Remote Task Input 通过 `POST /eve/v1/task-input/:token` 返回；`mcpChannel()` 提供 Durable `agent_start`、`agent_get`、`agent_update` 与 `agent_cancel` 工具。Eveland 会让 Child-stream Proxy 继续使用 Parent SessionBinding，并让 Create-once 与 Invocation Traffic 在加权发布、Promote/Rollback 与 Cold Activation 期间保持 Durable Deployment Routing。Eve 0.37.1 还修复了 `eve init` 的 Package Manager Detection、CommonJS Native Module 动态加载、Vercel Auth-stream 错误处理，以及多处 Task/Authorization 清理竞态。

**Eve 0.38 用 Durable `cancel()` 替换前端 `stop()`，并把 Workflow 提升到 spec v6。** Eveland Playground 现在等待 Hook 自己的 `cancel()`，包括首个 Event 尚未给出 Durable Turn ID 的阶段，并在 Settlement 前保持 Stream Attached。平台注入 `@workflow/world-postgres@5.0.0-beta.34` 或 `@evelandhq/workflow-world@0.7.0`；旧 spec-v5 World 会被 Eve 0.38.3 的启动门禁拒绝。共享 World 还通过 Snapshot stripping、Block packing、Checkpoint 和基于 Deadline 的 Retention 限制物理 Stream 存储增长。MCP Channel 默认路径变为 `/eve/v1/mcp`，也可显式声明其他 `route`；Eveland 的 Path-transparent Gateway 会保留两种路径及其对应的 OAuth Protected-resource Metadata Route。Eve 0.38 还引入 Extension Channel、Schedule 与带 Namespace 的 Subagent；它们完整的平台 Scheduler/Observer 集成由独立的兼容 Follow-up 提供。

对于当前最新支持线，即使 `^0.38.0` 等 Range 已允许新 Patch，Agent 项目也应刷新 Lockfile 并重新部署，才能实际获得 `0.38.3`。自定义 NDJSON Consumer 必须忽略空行，也不得把 Background-task Receipt 当作终态；如果 Relay/Proxy 自己管理恢复，可以使用 Reconnect Opt-out；普通 Agent Client 应保留默认 Live Follow。只有在两端 Deployment 都升级、且接收端能精确识别可信 Forwarder 后，才应启用 Remote Principal Forwarding。

仅有 npm Publication 不会扩大窗口。新 Minor 只有在 Changelog/Source Review 与完整 Compatibility Matrix 通过后才进入；移除旧 Minor 同样是显式产品变更。

## Enforcement Point

依赖缺失、超出窗口或无法证明兼容时，Eveland 会在以下位置 Fail Closed：

- Source Import 与 Preflight
- Build 与 Restart
- Cold Activation
- Playground Traffic
- Public Session Create、Continue、Cancel 与 Stream
- Public Session Reset
- Schedule Execution

Diagnostic 会要求项目 Owner Upgrade，而不是猜测旧 Protocol。生产环境升级 Eve 或 Eveland 前都应阅读 Release Note。
