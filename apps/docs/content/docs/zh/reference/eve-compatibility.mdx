---
title: Eve 兼容性
description: 理解 Eveland 已验证的 Eve 版本窗口与 Fail-closed Policy。
---

在 Eve 发布稳定 Compatibility Contract 之前，Eveland 支持最近三个经过完整验证的 Eve Minor Line。当前代码中的产品契约支持 `0.29.x`、`0.30.x` 与 `0.31.x`，验证版本为 `0.29.5`、`0.30.8` 与 `0.31.0`。

UI 仅将最新支持线 `0.31.x` 标为绿色。较旧但仍受支持的版本保持可运行，不过会以红色显示并提醒升级；不受支持的版本同样显示为红色且继续阻断。

窗口此前依赖 Eve 0.27 的能力现在都是基线：通过 `POST /eve/v1/session/reset` 的 Durable Session Reset、通过 `session.stream({ follow: false })` 与 `x-eve-stream-tail-index` Header 的有界 Catch-up Read、符合标准的 Route Auth Challenge，以及默认关闭的 Remote Principal Forwarding。Eveland 在公开路径与 Playground 路径都原样保留这些 Query、Header 与无缓冲 NDJSON Body，且从不替 Agent 开启信任、重写 Principal 或转发 Credential。Eve 0.27.3 及以后要求 AI SDK `ai@^7.0.34`，若项目单独钉死了更旧的 AI SDK，应一并升级。

**Eve 0.30 改变了 `localDev()`；导入的 Agent 若直接升级而不做处理，会被挡在 Playground 之外。** 它不再看请求的 Host，只在进程是 `eve dev` / `vercel dev` 时才返回 Session。Agent 在 Eveland 上以 `eve start` 运行，因此 `localDev()` 从此不再放行任何请求。框架默认 Channel 还新增了 `placeholderAuth()`，而它只在 `VERCEL_ENV=production` 时才抛出那条友好的 "Production auth is not configured"；自托管 Eveland 下它返回 null，Auth Walk 走空，Route 只给出一个不带任何解释的裸 401。需要改什么见[将 Agent 迁移到 Eve 0.30](/docs/agents/migrate-eve-0-30)。

Eve 0.30.5 还重命名了 Durable Cancellation Hook。`sessionCancelHookToken(sessionId)` 原本产生 `{sessionId}:cancel`，现在稳定的命令收件箱是 `eve:session:{sessionId}:inbox`，并由它转发一个私有的按 Turn 的 Hook。手工 resume 旧 token 来取消 Turn 的 Agent 代码在升级后会**静默失效**。走 HTTP `POST /eve/v1/session/:id/cancel` 的不受影响——该 Route 与响应 Schema 均未变，Eveland 自己用的就是它。

**Eve 0.31 移除了 Continuation-token Session API。** Session 只按固定 ID 寻址：TypeScript Client 改用 `client.sessions.create(input)` 与 `client.sessions.attach(sessionId)`，移除了 `client.session()`；Channel Route 拿到的是 `from(address)`、`to(channel, target)` 与 `attachSession(sessionId)`，不再有 `receive`/`send`；Schedule Handler 用 `to(channel, target).send(message, { auth })` 取代 `receive(channel, { message, target, auth })`。Clear、Compact 与 Reset 移到 `POST /eve/v1/session/:sessionId/{clear,compact,reset}`，请求与响应 Body 都不再携带 Continuation Token。已接受的异步操作回答 HTTP `202`；对非活跃 Session 的后续请求回答 HTTP `409` 与 `code: "session_not_active"`。Eveland 的 Gateway、Playground 与注入的 Scheduler Adapter 会按 Deployment 的 Eve 版本讲对应代际的协议，`0.29.x`/`0.30.x` Agent 无需改动——但迁移到 `0.31.x` 的 Agent 代码必须自行采用新 Surface。

对于当前最新支持线，即使 `^0.31.0` 等 Range 已允许新 Patch，Agent 项目也应刷新 Lockfile 并重新部署，才能实际获得 `0.31.0`。自定义 NDJSON Consumer 必须忽略空行；如果 Relay/Proxy 自己管理恢复，可以使用 Reconnect Opt-out；普通 Agent Client 应保留默认 Live Follow。只有在两端 Deployment 都升级、且接收端能精确识别可信 Forwarder 后，才应启用 Remote Principal Forwarding。

仅有 npm Publication 不会扩大窗口。新 Minor 只有在 Changelog/Source Review 与完整 Compatibility Matrix 通过后才进入；进入时会有意识地移除较旧 Minor。

## Enforcement Point

依赖缺失、超出窗口或无法证明兼容时，Eveland 会在以下位置 Fail Closed：

- Source Import 与 Preflight
- Build 与 Restart
- Cold Activation
- Playground Traffic
- Public Session Create、Continue、Cancel 与 Stream
- Public Session Reset
- Schedule Execution

Diagnostic 会要求项目 Owner Upgrade，而不是猜测旧 Protocol。生产环境升级 Eve 或 Eveland 前都应阅读 Release Note。
