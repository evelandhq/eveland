Eveland 0.16 把验证过的 Eve 补丁基线移到 `0.27.12`，并为公开数据面上的三处资源加上界。本文说明如何将生产环境从 `v0.15.0` 升级到 `v0.16.0`。

## 运维影响

**本次发布没有任何数据库 Migration。** 这是与 0.15 最大的区别——后者需要四个。本次没有任何改写数据行或变更 Schema 的操作，因此重新 Checkout `v0.15.0` 就是完整的回滚，详见回滚一节。

没有新增必填环境变量，宿主机前置条件不变，升级期间 Agent 持续服务流量。既有 Session、Route 与 Deployment 都不受影响。

Eve 支持范围不变：仍接受使用 `0.25.x`、`0.26.x` 与 `0.27.x` 的导入 Agent。兼容性矩阵现在验证 `0.25.3`、`0.26.2` 与 `0.27.12`。

### 预期中的行为变化

- **公开上游请求现在有 socket 空闲超时**，默认 120 秒（`EVELAND_GATEWAY_UPSTREAM_TIMEOUT_MS`）。它是**空闲**超时而非总时限：流式 NDJSON 会持续重置它，长任务不受影响。它拦截的是"接受连接却始终不应答"的 Deployment——这种情况此前会无限期占住客户端、socket，以及不断续期的 activation lease。只有当你的某个 Agent 确实会超过两分钟不发任何字节时才需要调高。
- **Gateway 的主机名 Route 缓存有了 1000 条上界。** 此前对允许基础域下未知子域的请求会让它随进程生命周期一直增长。逐出优先清理已过期条目，再按插入顺序淘汰最旧的；在 5 秒 TTL 下正常运行中不可察觉。
- **用量与实验视图的单次请求开销下降。** `variant-metrics` 改为 SQL 聚合，不再加载 Project 有史以来的全部 Session；用量看板也不再为每条用量事件重复传输整行 Session。数字本身不变。

## 1. 备份并安装

按现有流程备份 Postgres 与 `EVELAND_DATA_DIR`，然后停止宿主机 Worker：

```bash
sudo systemctl stop eveland-worker
```

在控制面 Checkout 中：

```bash
git fetch --tags origin
git checkout v0.16.0
pnpm install --frozen-lockfile
pnpm --filter @eveland/api db:migrate
git rev-parse --short=12 HEAD
```

`db:migrate` 仍值得执行——数据库已是最新时它是 no-op，同时也确认了 0.15 的四个 Migration 都已应用。

把打印出的 Revision 作为 `EVELAND_REVISION` 写入共享生产环境，并保持 `EVELAND_RELEASE_CHANNEL=stable`。

把 Worker Checkout 更新到同一 Tag 并重新构建 vendored sandbox backend：

```bash
cd /opt/eveland
git fetch --tags origin
git checkout v0.16.0
pnpm install --frozen-lockfile
pnpm --filter @eveland/sandbox-bwrap build
git rev-parse --short=12 HEAD
```

在 `/etc/eveland/eveland-worker.env` 中设置相同的 Revision 与 `stable` 渠道。

## 2. 启动发布

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml config
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
sudo systemctl start eveland-worker
sudo journalctl -u eveland-worker -n 100 --no-pager
```

## 3. 验证

1. API 与 Gateway `/health` 返回 `version: 0.16.0`、`channel: stable` 以及相同的 Revision。
2. **Settings → About** 中 Web、API、Gateway 与 Worker 的 build identity 一致。
3. 运行一次 Playground 对话，确认 Session、Node、Event 与 Usage 都出现。
4. 打开 **Usage** 和某个 Project 的实验视图；同一时间窗口的数字应与 0.15 报告的一致。
5. 如果有 Agent 的流式输出存在很长的空档，跑一次并确认流能正常结束。若在约两分钟静默后被切断，说明需要调高 `EVELAND_GATEWAY_UPSTREAM_TIMEOUT_MS`。

## 4. 让 Agent 用上 Eve 0.27.12

验证基线移到 `0.27.12` 并不改变已部署 Agent 实际运行的版本。Agent 只有在自己的依赖解析到该版本时才会用上它——也就是刷新 lockfile 并重新部署。固定在支持范围内更旧补丁的 Agent 继续照常工作。

## 回滚到 0.15

由于本次发布没有 Migration，源码回滚就足够：停止 Worker 与控制面服务，在两个位置 Checkout `v0.15.0`，重新安装 frozen lockfile，重新构建 `@eveland/sandbox-bwrap`，恢复此前的 Revision，启动 Compose，最后启动 Worker。数据库无需恢复。

唯一无法随之回滚的是你在第 4 步中针对 Eve 0.27.12 重新部署过的 Agent：那些 Release 会保持构建时的依赖，直到你再次重新部署。

关于不随版本变化的通用升级流程，见[升级与回滚](/docs/operations/upgrades)。本文提到的每个变量，见[配置](/docs/reference/configuration)。
