Eveland 将控制面与公开 Agent 流量、具有宿主机特权的运行时控制器分离。

<RuntimeTopology />

## 应用边界

| 应用 | 职责 |
| --- | --- |
| Web | 管理 Projects、Deployment、Playground、Sessions、Usage、Source、Secrets 与 Logs 的控制台。 |
| API | 控制面 HTTP 契约、持久化、导入处理与内嵌 Observer Collector。 |
| Gateway | 基于 Host 的公开 Agent 数据面、Session 亲和性、Streaming 与内部 Playground 路径。 |
| Worker | 构建、启动、停止、重启和清理 Deployment 的 Job Consumer。 |

应用之间互不导入。共享契约与持久化位于 Packages 中：

```text
apps → packages
packages/db → packages/core
packages/core → 不依赖其他 Eveland package
apps -X→ apps
```

## 数据路径

控制面状态保存在 Postgres。导入源码、准备好的 Release、加密环境文件、Observer outbox 与 Sandbox cache 保存在配置的 Eveland data directory 下。

Observer Hook 将持久 Envelope 写入 Deployment 专属 outbox。API 的内嵌 Collector claim、校验并以 exactly-once 方式投影为 Session 与 Usage 记录。

## 信任边界

- Gateway 处理公开请求体，但不能访问导入的 Project 数据。
- API 加密 Secrets，并且永不返回 Secret value。
- Worker 拥有运行时 Controller，并在配置的 Build Sandbox 中构建不受信任的项目依赖树。
- 生产 Deployment 使用无特权用户运行，并受到 systemd 文件系统、权限、CPU 与内存限制。
- Agent 执行使用注入的 bubblewrap Sandbox Backend 与 Project 专属持久 Cache。

## 请求路径

```text
Client
  → wildcard HTTPS host
  → Traefik
  → Gateway
  → route policy + session binding
  → private deployment port
  → Eve HTTP channel
```

Gateway 会保留 Agent 自己的 Authorization header、Cookie、请求体与 Streaming response。它负责路由，不替代 Agent 的应用认证。
