---
title: Eve compatibility
description: Understand Eveland's verified Eve version window and fail-closed policy.
---

Until Eve publishes a stable compatibility contract, Eveland supports a sliding window of the latest three fully verified Eve minor lines. The current checked-in product contract supports `0.25.x`, `0.26.x`, and `0.27.x`, verified at `0.25.3`, `0.26.2`, and `0.27.3`.

The UI marks only the latest supported line, `0.27.x`, in green. Older supported lines stay operational but appear in red with an upgrade reminder; unsupported versions also appear in red and remain blocked.

Eve 0.27 moves Nuxt deployments to Vercel's stable services model, improves compaction and prompt caching, and makes Route Auth advertise standards-compliant challenges. HTTP Basic now advertises its realm and UTF-8 charset and compares credentials after Unicode NFC normalization. Eveland does not host imported Agents through Eve's Nuxt integration and does not infer a Connection method from a 401 challenge, so these changes require no adapter branch.

The 0.27.1–0.27.3 patches improve workflow concurrency and cancellation, queued channel delivery, Slack and Teams routing, prefixed callback routes, dynamic-tool refresh, sandbox seed ordering, and diagnostics. Eve 0.27.2 also sends an initial whitespace byte when opening an NDJSON stream and lets Client callers opt out of automatic stream reconnection. Eveland's stream monitor already ignores blank lines, Gateway forwards the byte without buffering, and the Playground keeps the default durable reconnect behavior. The canonical session/continuation/cancel/stream routes, Vercel OIDC headers, observer hook events, schedule/channel definitions, and `SandboxBackend` contract remain compatible across the verified window.

Agent projects should refresh their lockfile and redeploy to receive `0.27.3`, even when a range such as `^0.27.0` already permits it. Eve 0.27.3 also requires AI SDK `ai@^7.0.34`; update a separately pinned or locked older AI SDK at the same time. Custom NDJSON consumers must ignore blank lines. Relay or proxy code may use Eve's explicit reconnect opt-out when it owns reconnection itself; ordinary Agent clients should keep the default.

An npm publication alone does not widen the window. A new minor enters only after changelog and source review plus the complete compatibility matrix. When it enters, the older supported minor leaves the window deliberately.

## Enforcement points

Eveland fails closed when the dependency is missing, outside the window, or cannot be proven compatible during:

- source import and preflight
- build and restart
- cold activation
- Playground traffic
- public session create, continue, cancel, and stream
- schedule execution

The diagnostic asks the project owner to upgrade instead of guessing an older protocol. Review the release notes before upgrading either Eve or Eveland in production.
