---
title: Eve compatibility
description: Understand Eveland's verified Eve version window and fail-closed policy.
---

Until Eve publishes a stable compatibility contract, Eveland supports a sliding window of the latest three fully verified Eve minor lines. The current checked-in product contract supports `0.27.x`, `0.28.x`, and `0.29.x`, verified at `0.27.13`, `0.28.0`, and `0.29.4`.

The UI marks only the latest supported line, `0.29.x`, in green. Older supported lines stay operational but appear in red with an upgrade reminder; unsupported versions also appear in red and remain blocked.

Eve 0.27 moves Nuxt deployments to Vercel's stable services model, improves compaction and prompt caching, and makes Route Auth advertise standards-compliant challenges. HTTP Basic now advertises its realm and UTF-8 charset and compares credentials after Unicode NFC normalization. Eveland does not host imported Agents through Eve's Nuxt integration and does not infer a Playground authentication method from a 401 challenge, so these changes require no adapter branch.

The 0.27.1–0.27.3 patches improve workflow concurrency and cancellation, queued channel delivery, Slack and Teams routing, prefixed callback routes, dynamic-tool refresh, sandbox seed ordering, and diagnostics. Eve 0.27.2 also sends an initial whitespace byte when opening an NDJSON stream and lets Client callers opt out of automatic stream reconnection. Eveland's stream monitor already ignores blank lines, Gateway forwards the byte without buffering, and the Playground keeps the default durable reconnect behavior.

Eve 0.27.4 adds durable session reset through `POST /eve/v1/session/reset`. Eveland stores the latest continuation token with its SessionBinding, so token-only resume and reset stay pinned to the Deployment that owns the durable workflow even after promote, rollback, or weight changes. A successful reset clears that token binding; the historical session-to-Deployment binding remains for streams, observation, and retention. Migration `0029_sparkling_hammerhead` backfills known tokens before adding the unique routing index.

Eve 0.27.6 adds explicit principal-metadata forwarding for remote Agents, ignores an empty remote `outputSchema`, and fixes remote create/cancel URLs below a base path. Forwarding remains disabled by default. The sender must set `forwardPrincipal: true`, and the receiving Agent must define a precise `trustedForwarders` predicate. Eveland transparently proxies the body and Agent-owned authentication but never enables trust, rewrites the principal, or forwards credentials. The canonical create/continue/cancel/stream messages, Vercel OIDC headers, Eve hook events, schedule definitions, and `SandboxBackend` contract otherwise remain compatible across the verified window.

Eve 0.27.7 adds bounded catch-up reads through `session.stream({ follow: false })`. The Client requests `includeTailIndex=1`, the Eve route returns `x-eve-stream-tail-index`, and the read stops at the durable tail observed when it opened. Eveland preserves that query, response header, and NDJSON body without buffering on both public and Playground paths. Bounded reads require both Client and Agent to run Eve 0.27.7 or later; an older Agent does not emit the tail header, so the new Client fails explicitly instead of silently following forever. The existing Playground keeps the default live-follow behavior. The same patch parses provider-executed tool arguments delivered as raw JSON strings and converts malformed arguments into a failed tool result instead of failing the whole turn; Eveland's private telemetry hook receives the normal resulting event flow. Its single-Nitro-build optimization applies only to Eve's Vercel output and does not change Eveland's standalone Release build.

Eve 0.27.8 adds the authoring-time `eve add` and `eve registry` commands. Eveland does not run these commands during import or deployment, so they do not mutate an imported source snapshot or grant a Release extra network, filesystem, or sandbox privileges.

Projects that depend on those commands must use Eve 0.27.8 or later. For the current latest line, Agent projects should refresh their lockfile and redeploy to receive `0.29.4`, even when a range such as `^0.29.0` already permits it. Eve 0.27.3+ requires AI SDK `ai@^7.0.34`; update a separately pinned or locked older AI SDK at the same time. Custom NDJSON consumers must ignore blank lines. Relay or proxy code may use reconnect opt-out when it owns recovery, and may use `follow: false` only when the target Agent is also on Eve 0.27.7+; ordinary Agent clients should keep the default live follow. Only enable remote principal forwarding after both deployments are upgraded and the receiver can name the exact trusted forwarder.

An npm publication alone does not widen the window. A new minor enters only after changelog and source review plus the complete compatibility matrix. When it enters, the older supported minor leaves the window deliberately.

## Enforcement points

Eveland fails closed when the dependency is missing, outside the window, or cannot be proven compatible during:

- source import and preflight
- build and restart
- cold activation
- Playground traffic
- public session create, continue, cancel, and stream
- public session reset
- schedule execution

The diagnostic asks the project owner to upgrade instead of guessing an older protocol. Review the release notes before upgrading either Eve or Eveland in production.
