---
title: Eve compatibility
description: Understand Eveland's verified Eve version window and fail-closed policy.
---

Until Eve publishes a stable compatibility contract, Eveland supports only minor lines that have passed the complete compatibility matrix, and changes that window explicitly. The checked-in product contract supports `0.37.x` and `0.38.x`, verified at `0.37.1` and `0.38.3`. Eve 0.34–0.36 are no longer accepted for import, build, restart, activation, Playground, Gateway, or schedule execution.

The UI marks only the latest supported line, `0.38.x`, in green. Eve 0.37.x stays operational but appears in red with an upgrade reminder; unsupported versions also appear in red and remain blocked.

Everything the window relied on from Eve 0.27 is now baseline: durable session reset through `POST /eve/v1/session/reset`, bounded catch-up reads through `session.stream({ follow: false })` and its `x-eve-stream-tail-index` header, standards-compliant Route Auth challenges, and opt-in remote principal forwarding. Eveland preserves those queries, headers, and NDJSON bodies without buffering on both the public and Playground paths, and never enables forwarding trust, rewrites a principal, or forwards credentials on an Agent's behalf. Eve 0.27.3 and later require AI SDK `ai@^7.0.34`, so a separately pinned older AI SDK must be updated at the same time.

Everything the window relied on from Eve 0.30 is now baseline too: `localDev()` is process-based rather than Host-based, so it admits nothing under `eve start` — Agents on Eveland must authenticate with `evelandIdentity()`, `httpBasic()`, or OIDC. See [Migrating an Agent to Eve 0.30](/docs/agents/migrate-eve-0-30). The durable cancellation hook is the command inbox `eve:session:{sessionId}:inbox`; Agent code that manually resumed the old `{sessionId}:cancel` token **fails silently**. Cancelling over HTTP with `POST /eve/v1/session/:id/cancel` is unaffected — that route and its response schema are unchanged, and it is what Eveland itself uses.

Everything the window relied on from Eve 0.31 is now baseline too: sessions are addressed only by their ID, TypeScript clients use `client.sessions.create(input)` and `client.sessions.attach(sessionId)`, channel routes receive `from(address)`, `to(channel, target)`, and `attachSession(sessionId)`, and schedule handlers receive `to(channel, target).send(message, { auth })`. Clear, compact, and reset live at `POST /eve/v1/session/:sessionId/{clear,compact,reset}`. Accepted asynchronous work answers HTTP `202`; follow-ups on an inactive session answer HTTP `409` with `code: "session_not_active"`.

Eve 0.32's sandbox contract is the whole window's baseline: a custom sandbox backend handle must implement `stop()`. A backend that implements only `captureState()` and `shutdown()` compiles against the older typings but throws at runtime the first time an authored hook, tool, or channel callback calls `ctx.getSandbox().stop()`. Unlike `shutdown()`, `stop()` must preserve the durable session so a later callback can reopen it. Eveland's own `@evelandhq/sandbox-bwrap` implements it from `0.1.1`. Eve 0.32 also renames the negative tool-approval response from `deny` to `cancel`, and binds interactive connection authorization callbacks to a specific attempt (`/eve/v1/connections/:name/callback/:attemptId/:token`).

**Eve 0.33 makes `turnPolicy: "steer"` the default for channel message sends.** A message that arrives while a turn is running now cancels and replaces that turn instead of waiting for it to finish. Set `turnPolicy: "queue"` on the channel or the individual send to keep the previous behavior — Eveland's injected scheduler adapter does exactly that, so a schedule never preempts a turn a person is waiting on. Eve 0.33 also removed the compiled fallback for dynamic models and subagents: `defineDynamic` accepts only `events`, a dynamic model handler must return a concrete selection, and a dynamic subagent must name a static model. The configured model id moved off the `session.started` runtime identity onto each `step.started` event.

**Eve 0.34 posts human-in-the-loop prompts into the GitHub thread by default.** An Agent using `githubChannel` now writes pending input requests as issue or pull request comments so a person can answer them there; nothing else is required, but the comments are new and visible. Eve 0.34 also lets a tool or connection declare `approval` as `{ request, response }` instead of a bare function — the response policy authenticates the responder and returns a tagged allow or rejection — and the function shorthand keeps working unchanged. The experimental `agent/instrumentation/` provider directory arrives behind `experimental.instrumentationProviders`; it is mutually exclusive with a single `agent/instrumentation.ts`, and enabling one makes the other a build error. `defineInstrumentation` no longer rejects unknown keys at `tsc` time, so a misspelled option now surfaces at `eve build`.

**Eve 0.35 makes instrumentation content opt-in and introduces role-aware instructions.** Eve's own instrumentation records model and tool inputs/outputs only when `recordInputs`/`recordOutputs` are enabled (or `EVE_TRACES_CONTENT=on` is set for local traces). Eveland's injected private observer remains independent of that switch and continues to follow the Project's Eveland capture policy. Instruction modules now use `content` plus an optional `system` or `user` role; legacy `markdown` is deprecated, and user-role instructions become durable model history. Session and turn start events may also include optional portable trace context. Current supported builds emit discovery manifest v13; the projector still accepts v12 for immutable historical artifacts.

**Eve 0.36 changes the default model to `zai/glm-5.2`.** A project that relied on Eve's implicit default can therefore change provider, behavior, credentials, and cost after rebuilding. Pin `model` explicitly before upgrading. The `eve/sveltekit` integration also moves to the stable Vercel services model and removes `configureVercelJson`, `servicePrefix`, and `EVE_SVELTEKIT_SERVICE_PREFIX`; projects using those options must migrate their source before deploying.

**Eve 0.37 adds Vercel Sandbox Drives and adjusts authoring-time CLI behavior.** Eveland still replaces an authored sandbox backend with its managed bwrap backend while preserving workspace seeds, so Vercel Drive mounts are not exposed by an Eveland deployment. The `eve init`/`eve dev` changes affect local authoring, not the platform's explicit build and start commands.

**Eve 0.37.1 adds durable background work and invocation channels.** A `subagent.completed` event that carries `backgroundTask: { status: "working" }` is a receipt, not the child's terminal event; consumers must follow the child stream for completion. Remote child streams may be followed through their parent at `GET /eve/v1/session/:parentSessionId/subagents/:callId/:childSessionId/stream`. Authenticated callers can make session creation idempotent with `operationId`, remote task input returns through `POST /eve/v1/task-input/:token`, and `mcpChannel()` exposes durable `agent_start`, `agent_get`, `agent_update`, and `agent_cancel` tools. Eveland preserves the parent SessionBinding for the child-stream proxy and keeps create-once and invocation traffic on its durable Deployment routing boundary across weighted promotion, rollback, and cold activation. Eve 0.37.1 also fixes package-manager detection in `eve init`, dynamic loading of CommonJS-native modules, Vercel auth-stream error handling, and several task/authorization cleanup races.

**Eve 0.38 replaces frontend `stop()` with durable `cancel()` and moves Workflow to spec v6.** Eveland's Playground now awaits the hook-owned `cancel()` command, including the interval before the first event identifies the durable turn, and keeps the stream attached through settlement. The platform injects `@workflow/world-postgres@5.0.0-beta.34` or `@evelandhq/workflow-world@0.7.0`; older spec-v5 worlds fail Eve 0.38.3's startup guard. The shared World also bounds physical stream storage with snapshot stripping, block packing, checkpoints, and deadline-driven retention. MCP channels now default to `/eve/v1/mcp` and may declare another `route`; Eveland's path-transparent Gateway preserves either path and the corresponding OAuth protected-resource metadata route. Eve 0.38 also introduces extension-provided channels, schedules, and namespaced subagents; their full platform scheduling and observer integration is delivered as a separate compatibility follow-up.

For the current latest line, Agent projects should refresh their lockfile and redeploy to receive `0.38.3`, even when a range such as `^0.38.0` already permits it. Custom NDJSON consumers must ignore blank lines and must not treat a background-task receipt as terminal. Relay or proxy code may use reconnect opt-out when it owns recovery; ordinary Agent clients should keep the default live follow. Only enable remote principal forwarding after both deployments are upgraded and the receiver can name the exact trusted forwarder.

An npm publication alone does not widen the window. A new minor enters only after changelog and source review plus the complete compatibility matrix; removing an older minor is also an explicit product change.

## Enforcement points

Eveland fails closed when the dependency is missing, outside the window, or cannot be proven compatible during:

- source import and preflight
- build and restart
- cold activation
- Playground traffic
- public session create, continue, cancel, and stream
- public session reset
- schedule execution

The diagnostic asks the project owner to upgrade instead of guessing an older protocol. Review the release notes before upgrading either Eve or Eveland in production.
