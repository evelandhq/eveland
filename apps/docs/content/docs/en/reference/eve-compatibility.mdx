---
title: Eve compatibility
description: Understand Eveland's verified Eve version window and fail-closed policy.
---

Until Eve publishes a stable compatibility contract, Eveland supports a sliding window of the latest three fully verified Eve minor lines. The current checked-in product contract supports `0.24.x`, `0.25.x`, and `0.26.x`, verified at `0.24.6`, `0.25.3`, and `0.26.2`.

The UI marks only the latest supported line, `0.26.x`, in green. Older supported lines stay operational but appear in red with an upgrade reminder; unsupported versions also appear in red and remain blocked.

Eve 0.26 moves durable stream reconnection into the Client and removes the `maxReconnectAttempts` option. Eveland did not configure that option; its Playground now inherits cursor-based reconnection from Eve 0.26. The canonical session, continuation, cancel, and stream routes, Vercel OIDC headers, observer hook events, schedule/channel definitions, and `SandboxBackend` contract remain compatible across the verified window.

An npm publication alone does not widen the window. A new minor enters only after changelog and source review plus the complete compatibility matrix. When it enters, the older supported minor leaves the window deliberately.

## Enforcement points

Eveland fails closed when the dependency is missing, outside the window, or cannot be proven compatible during:

- source import and preflight
- build and restart
- cold activation
- Playground traffic
- public session create, continue, cancel, and stream
- schedule execution

The diagnostic asks the project owner to upgrade instead of guessing an older protocol. Review the release notes before upgrading either Eve or Eveland in production.
