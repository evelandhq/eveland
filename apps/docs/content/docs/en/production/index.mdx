Eveland's production boundary is intentionally different from its local development stack. Production Eve deployments do not run through the development Docker runtime.

<RuntimeTopology lang="en" />

## Control plane

Web, API, Gateway, and Postgres run with the production Compose overlay. API owns authenticated team workflows and persistence. Gateway is the only public Agent data plane and has neither the Docker socket nor access to source, releases, secrets, or observer outboxes.

## Host runtime controller

Worker runs directly on the Linux host as a root-owned systemd service. It is the only component allowed to build untrusted project code and control systemd units. Eve deployments run as the unprivileged application user on private `127.0.0.1:41xxx` ports.

## Shared data contract

API and Worker must see the same absolute data root, normally `/var/lib/eveland`. Imported sources, prepared releases, observer outboxes, and sandbox caches are exchanged through paths stored in Postgres, so a mismatched mount breaks the deployment path.

## Resource lifecycle

A durable Deployment is not the same thing as a permanently running process. Activation leases wake the exact Release for traffic, continuations, or schedules. After the final lease, Worker stops the RuntimeInstance following the configured idle period while the Deployment, preview address, and SessionBindings remain valid.
