---
title: Install the host Worker
description: Install the privileged Worker as a systemd service and connect it to the control plane.
---

Worker is the only runtime controller. Production keeps it on the host so API and Gateway never receive systemd or Docker-controller privilege.

## Install the service

```bash
sudo install -d -m 0750 /etc/eveland
sudo cp infra/systemd/eveland-worker.env.example /etc/eveland/eveland-worker.env
sudo cp infra/systemd/eveland-worker.service /etc/systemd/system/
```

Configure the environment file before starting the service. At minimum, align database access, `/var/lib/eveland`, application encryption, Agent domains, Gateway service authentication, workflow Postgres, scheduler secrets, release identity, and `EVELAND_RUNTIME=systemd` with the control plane.

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now eveland-worker
```

## Verify ownership boundaries

- Worker runs as root and controls `systemd-run`, `systemctl`, and filesystem ownership.
- Builds run as the unprivileged build user inside the configured build sandbox.
- Eve processes run as the unprivileged application user.
- Worker has no public listener.
- Project secrets reach only a root-owned `0600` EnvironmentFile for the target process.

Worker refuses to accept jobs when production preflight or the durable workflow configuration is incomplete. Check the service journal and the masked Worker configuration snapshot before moving on.
