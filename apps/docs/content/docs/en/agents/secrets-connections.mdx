---
title: Secrets and Agent Connections
description: Separate runtime environment values from credentials Eveland uses to call a protected Agent.
---

Eveland keeps two credential paths separate: values injected into the Agent process, and credentials used by Playground to call the Agent's own protected Eve route.

## Runtime secrets

Project Secrets are encrypted at rest and materialized only for the target process. Saving, replacing, or deleting one queues a targeted restart for every running or draining Deployment so no route keeps a stale environment.

Administrators can create revisioned Platform Secret Profiles. An `agent-runtime` profile can bind to a whole Project or one Deployment. Effective precedence is Project Secret, Project Profile, Deployment Profile, then Eveland-reserved values.

## Agent Connections

From Playground, explicitly choose local development, no credential, Basic, Bearer, Vercel OIDC, custom headers, or generic OIDC Authorization Code. Eveland never infers the method from source, provider name, or an authentication challenge.

Secret-bearing connection fields select a Project Secret or a bound `agent-connection` profile entry. API resolves the current reference for each create, continue, cancel, and stream request; the credential never enters Web or Gateway storage.

## Rotation behavior

- Runtime-secret changes restart affected live Deployments.
- Agent-connection changes resolve per request and do not restart the Agent.
- Deleted values fail closed instead of falling back to an older plaintext copy.
- Secret values are added to diagnostic masking and never returned through client APIs.
