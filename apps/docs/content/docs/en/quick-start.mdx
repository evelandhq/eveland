title: Quick Start

This guide runs Postgres in Docker and the four Eveland applications natively. It is the fastest path for development on macOS or Linux.

## Prerequisites

- Node.js 24 or newer
- Corepack with pnpm enabled
- Docker with Compose
- A local Eve project, Git URL, or Zip archive

## Install and start

```bash
git clone https://github.com/evelandhq/eveland.git
cd eveland
pnpm install

docker compose up -d postgres
pnpm --filter @eveland/api db:migrate

pnpm --filter @eveland/api dev
pnpm --filter @eveland/gateway dev
pnpm --filter @eveland/web dev
pnpm --filter @eveland/worker dev
```

Open [http://localhost:3000](http://localhost:3000). All four applications are required: Web provides the control panel, API stores control-plane state, Worker performs import/build/deploy jobs, and Gateway routes Playground and public agent traffic.

> Pick one development mode. Run the whole stack in Compose, or run only Postgres in Compose and the applications natively. Switching between the two against the same mounted workspace can replace platform-specific `node_modules`.

## Import a project

1. Open **Projects** and choose **New project**.
2. Import a Git repository or upload a Zip file.
3. Wait for source validation to finish.
4. Add the environment variables and provider keys required by the agent.
5. Choose **Build & Deploy**.

The first successful deploy creates an immutable release and a preview deployment. Open **Playground** for a fresh continuous conversation through Gateway. It streams messages, live thinking, tool calls and results, supports approval, choice, text, and external-authorization prompts, and accepts up to four image, PDF, text, or code files. Reloading the page starts a new conversation; the generated platform Session remains available under **Sessions**.

## Configure protected Agents

Open **Playground → Connection** and explicitly choose how Eveland calls the Agent's Eve route. Local development, no credential, HTTP Basic, Bearer, custom headers, and generic OIDC Authorization Code are available; Eveland does not infer this choice from Agent source or an authentication challenge.

For OIDC:

1. Register `<your Web origin>/agent-auth/oidc/callback` as the client's exact redirect URI.
2. For a confidential client, create a Project Secret containing the client secret, then enter that Secret's key in the Connection. Public clients choose `none` and do not need a Secret.
3. Configure issuer, client id, scopes, optional audience and parameter mode, token endpoint authentication, optional authorization parameters, and either Eve JWT or UserInfo verification.
4. Save the Connection, then choose **Authorize with identity provider** or send the first Playground message.

Each Eveland member authorizes an isolated credential. The first message waits in that browser session during the redirect and is sent exactly once after the callback. Access and refresh tokens remain encrypted in API storage and are never returned to Web.

## Verify the workspace

Run the same checks used by the repository before committing a change:

```bash
pnpm test
pnpm typecheck
```
