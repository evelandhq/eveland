---
title: Eve compatibility
description: Understand Eveland's verified Eve version window and fail-closed policy.
---

Until Eve publishes a stable compatibility contract, Eveland supports only minor lines that have passed the complete compatibility matrix, and changes that window explicitly. The checked-in product contract supports `0.45.x` and `0.47.x`, verified at `0.45.2` and `0.47.3`. Eve 0.46 is the window's skipped line, and Eve 0.44 and older are no longer accepted for import, build, restart, activation, Playground, Agent Gateway, or schedule execution.

The Eve dependency declarations a project's `package.json` may carry are: an exact patch inside a supported line, a `~`/`^` range anchored on a supported minor's patch, and the `0.45` / `0.45.x` / `0.45.*`, `0.47` / `0.47.x` / `0.47.*` forms. A missing Eve dependency, a broad cross-minor range, or any declaration that could resolve outside the window fails closed. The project Overview, Source, and Playground pages show the Eve dependency version of the current deployment's source revision alongside the platform requirement.

The window is a set of verified lines, not "everything at or above the floor": the current window is a gapped pair — `0.46.x` sits between the supported lines and is rejected even though it is inside their hull (0.46 was superseded by 0.47 within hours of release, as 0.40/0.41 and 0.43 were skipped before it), and `0.44.x`, supported in the previous window, is now rejected with the same upgrade diagnostic the moment it left.

The UI marks only the latest supported line, `0.47.x`, in green. Eve 0.45.x stays operational but appears in red with an upgrade reminder; unsupported versions also appear in red and remain blocked.

## Window baseline

Everything the platform once carried for older Eve lines is now the baseline of the whole window, and the pre-0.42 compatibility paths have been removed from Eveland entirely:

- Sessions are addressed only by their ID. Continuation tokens do not exist anywhere in the platform anymore: the token columns, the token-based reset translation, and the `POST /eve/v1/session/reset` token route are gone. Clear, compact, and reset live at `POST /eve/v1/session/:sessionId/{clear,compact,reset}`.
- `localDev()` is process-based and admits nothing under `eve start`; Agents on Eveland must authenticate with `evelandIdentity()`, `httpBasic()`, or OIDC.
- Channel message sends default to `turnPolicy: "steer"`; Eveland's injected scheduler adapter always asks for `"queue"` so a schedule never preempts a turn a person is waiting on.
- A custom sandbox backend handle must implement `stop()` that preserves the durable session, and on 0.47.x also `delete()`, which permanently removes the sandbox's disposable state while preserving shared template state; Eveland replaces an authored backend with its managed bwrap backend (`@evelandhq/sandbox-bwrap`), which implements both.
- Supported builds emit discovery manifest v14 (0.45.0) or v15 (0.45.1+ and 0.47.x); the projector accepts both and nothing older. v14 adds an optional `instrumentation` module reference; v15 adds the `memories` list.
- Eve's implicit default model is `zai/glm-5.2` on 0.45.x and `openai/gpt-5.6-luna-fast` from 0.47.2; pin `model` explicitly to control provider, behavior, and cost.
- Durable background work and invocation channels are baseline: remote child streams follow through the parent at `GET /eve/v1/session/:parentSessionId/subagents/:callId/:childSessionId/stream`, create-once `operationId` sessions, `POST /eve/v1/task-input/:token` callbacks, and `mcpChannel()`'s durable agent tools all ride Eveland's durable Deployment routing boundary. Because every supported line speaks these routes, the Agent Gateway no longer maintains a per-operation Eve version floor — the window itself is the gate.
- Frontend `stop()` is gone; cancellation is the durable, hook-owned `cancel()` command. Eveland's Playground awaits it, including the interval before the first event identifies the durable turn, and keeps the stream attached through settlement.
- Workflow runs on storage spec v6. The platform injects `@evelandhq/workflow-world@0.14.0` for every new build; `@workflow/world-postgres@5.0.0-beta.34` exists only in historical Releases and is never selected for a new build. Older spec-v5 worlds fail the startup guard. The shared World also bounds physical stream storage with snapshot stripping, block packing, checkpoints, and deadline-driven retention.
- MCP channels default to `/eve/v1/mcp` and may declare another `route`; Eveland's path-transparent Agent Gateway preserves either path and the corresponding OAuth protected-resource metadata route.
- Extensions may provide channels, schedules, and namespaced subagents; their full platform scheduling and observer integration is delivered as a separate compatibility follow-up.
- `chatgpt()` is stable with Codex-owned authentication — but ChatGPT subscription models are local-only by design: there is no Codex sign-in inside an Eveland deployment, so an Agent pinned to `chatgpt()` deploys and then fails at run time. Use an AI Gateway or server-authenticated model for deployed Agents.
- `glob` and `grep` are not in the default Agent tool set; an Agent that relies on them must export them from the corresponding tool files by re-exporting the provided definitions from `eve/tools/glob` / `eve/tools/grep` (the `defineGlobTool()` / `defineGrepTool()` factories left the window with 0.44).
- A child agent may return `parent.sandbox` from a `defineSandbox` callback to share the dispatching parent's live sandbox; such a child cannot also declare managed workspace or skill resources, and Eveland's managed backend replacement applies to the parent definition as usual.

**Eve 0.42 absorbs the skipped 0.40 and 0.41 lines.** From 0.40: `task_peek` is removed from experimental background tasks — task notifications now carry completed results and failures directly, so an Agent instructed to peek must rely on the notification instead, and a conditionally delivered task wake may stay silent when its result was already covered by an earlier response. The bundled Workflow SDK gains optional batched event writes (`WORKFLOW_BATCH_TRANSITIONS`, on by default) — the platform's injected World keeps the single-event write path, so run behavior is unchanged. `eve info --json` now emits valid JSON without the CLI banner. From 0.41: a first-class Linq iMessage/SMS channel — note its managed Vercel Connect setup path does not work inside an Eveland deployment (like `chatgpt()`, there is no Vercel Connect session there); use the portable partner-API-token path instead. From 0.42 itself: channel and session `respond()` calls now accept only exact response literals or values proven by `parseInputResponses()`, so channel-local metadata cannot leak into durable session-inbox payloads, and the `task_sleep` framework tool is removed — task-mode parents rely on lifecycle notifications instead of model-paced waits.

**Eve 0.44 absorbs the skipped 0.43 line.** From 0.43: a tool may declare `execution: "background"` and return a `task.delegated()` receipt, and a background executor reports progress and the task's terminal result in-process through `task.send({ kind: "complete" | "fail" | "cancel" })`; local and remote subagents run through that same background-tool path when `experimental.tasks` is enabled. Dynamic-tool approval, execute, and output callbacks are durable across cold starts — a callback that captures a non-serializable value now fails with an actionable error instead of silently losing it on replay. Remote subagent continuations forward the caller on every follow-up turn, so upgrade both deployments before resuming a persistent remote session: a receiver that accepts forwarding only at session creation rejects such a continuation with HTTP 400 (the parent keeps the child handle; retry after upgrading the receiver). From 0.44 itself: Eve's own OpenTelemetry export is public-audience-only by default — built-in messaging channels classify conversations as `public`, `private`, or `unknown`, and sessions reached over HTTP (Eveland's Playground and Agent Gateway) are `unknown`. Eveland's observer is unaffected because it is an injected hook with its own exporter pipeline, but an Agent that declares its own `otel()` / `agentRuns()` / `otelIntegration()` stops seeing Playground and Gateway sessions on its backend unless it sets `otel({ tracePolicy: () => true })`; `recordInputs` / `recordOutputs` are deprecated in favor of an `exportPolicy` composed from `redactSpanInputs()` / `redactSpanOutputs()`. Under `eve dev`, the local trace spool now records prompts and outputs unless `EVE_TRACES_CONTENT=off`.

**Eve 0.44.3 is a patch slide inside the same line.** 0.44.1 redacts model, tool, approval, and delivery content from Eve's own hosted instrumentation for `private` and `unknown` audiences, so Playground and Agent Gateway sessions export metadata only through an Agent's own `otel()`; the workflow run attributes gain `$eve.is_trace_content_visible` and omit the content-derived `$eve.title` for those runs. Eveland's observer and the shared World are unaffected (both read lifecycle events and structural attributes, never Eve's instrumentation content). Dynamic-tool callbacks are now bound by tool name and phase instead of source position, so editing a callback body no longer risks a parked approval replaying the wrong code; a parked call whose tool disappeared fails closed. `useEveAgent` gains `resume: true` / `resume()` and `send(..., { turnPolicy: "steer" })`. Eve clients from 0.44.3 on reconnect after 15 seconds without stream bytes; the gateway therefore heartbeats every 5 seconds by default (`EVELAND_GATEWAY_STREAM_HEARTBEAT_MS`) so a proxied stream that is merely quiet stays attached instead of reconnecting through every hop.

**Eve 0.44.4 is a further patch slide with no platform-facing changes.** Slack inbound messages now derive their text from Block Kit blocks and legacy attachments when the top-level text is empty, so alert-style bot posts reach the model with their visible content instead of an empty body. `web_fetch` follows up to ten redirects, rechecking each destination for SSRF safety, and returns non-success HTTP responses as plain-text failure results instead of failing the tool call. A channel's `fetchFile` callback gains an optional context argument carrying the channel state. Web Chat resumes an active response even when the durable history still ends at the previous turn boundary. Eve no longer emits its own `workflow.stream.follow.read` tracing span.

**Eve 0.45 compiles every source through one authoritative source graph; the wire formats Eveland hosts are unchanged.** The message stream, session inbox, workflow storage spec, and bundled Workflow SDK are byte-identical to 0.44.4; the discovery manifest moves to v14 (additive, see the baseline note above), and the 0.45.1/0.45.2 patches move it again to v15 with the additive `memories` list for the new first-class memory providers (`eve/memory`). Note for memory adopters: `fileMemory()` resolves its storage backend automatically only under `eve dev` (process-local) and on configured Vercel deployments (Blob); on Eveland deployments an explicit backend must be passed, or the Agent fails at runtime. What Agent authors must know: the `eve/tools/defaults` entrypoint is removed in favor of per-tool `eve/tools/<name>` subpaths, and the `defineBashTool` / `defineReadFileTool` / `defineWriteFileTool` / `defineGlobTool` / `defineGrepTool` factories are removed — re-export the provided definitions instead. Persistent subagent sessions are now the default and `experimental.subagentPersistentSessions` is removed (`false` no longer opts out): subagent tools expose `agentId`, completed children stay available for follow-up messages, and the `<agents>` listing is published to the model automatically. Framework default config, sandbox, home, health, and inspection routes are replaceable by authored files, and a channel route can be removed with `disableRoute()`. Tools stay available on follow-up turns while an earlier approval is pending. Frontend clients gain a `resuming` lifecycle state while an attached session checks for an in-flight turn. Agent traces keep one identity from before workflow execution (Agent Trace schema v2, no rotation after 200 turns) and workflow rows carry `$eve.trace_id` when a sampled trace exists — Eveland's observer pipeline is unaffected.

**Eve 0.47 absorbs the skipped 0.46 line; the workflow storage spec and bundled Workflow SDK are byte-identical to 0.45.2.** From 0.46.0: Eve's own tracing default reverses the 0.44 public-only rule — spans are emitted for every audience while content is recorded only for `public` conversations, so an Agent's own `otel()` sees Playground and Agent Gateway sessions again as metadata-only spans without `tracePolicy: () => true` (explicit boolean policies keep their behavior; Eveland's observer is unaffected either way). From 0.46.1: the message stream protocol moves to v24 — tool inputs stream through the durable protocol as `action.input.appended` events carrying only a raw delta and its UTF-16 offset ahead of the validated `actions.requested` event, the default message reducer exposes the accumulated raw input as `inputText` on dynamic-tool parts in the `input-streaming` state, and when assistant text precedes a tool call `message.completed` now arrives before that call's streamed input events; MCP and OpenAPI `providedArguments` callbacks receive a replay-stable `callId` for per-call idempotency keys. From 0.47.0 itself: the runtime sandbox handle gains `delete()` — authored code may permanently remove the current session sandbox and have it reprovisioned on next access (see the baseline note; Eveland's managed bwrap backend implements it); sandbox `onSession` callbacks now receive only session metadata through `ctx` — auth and turn context are no longer available there, so move that work into `bootstrap` or channel/session handlers — while sandbox access during initialization goes through `use()`; scheduled background-task launches stay silent instead of sending a launch acknowledgement, and schedule-created workflow runs expose `$eve.schedule` for attribution; model slugs ending in `-thinking` now resolve to the correct model instead of failing or silently using the base model's context window. From 0.47.2: the implicit default model for config-less Agents moves to `openai/gpt-5.6-luna-fast` (see the baseline note — pin `model` explicitly).

**Eve 0.47.3 is a patch slide with no changes to anything Eveland hosts.** Every wire constant is identical to 0.47.2: message stream v24, discovery manifest v15, the workflow storage spec, and the bundled Workflow SDK. The patch's main addition is an activity subsystem for delegated subagents: a parent may pass an `activityObserver` when dispatching a remote child, and the child reports work, action, and blocker lifecycle by POSTing versioned batches to the parent's `POST /eve/v1/activity/:token` (the sink must share the delegated-callback origin). That route rides the Agent Gateway's ordinary public-request path — it activates a dormant Deployment and is window-gated like any other request, with no Gateway change. Instrumentation-provider content delivery now depends only on each provider's `capture` declaration, and a `tracePolicy` that drops the eve trace no longer disables AI SDK telemetry (metadata-only AI spans still land in the ambient Workflow trace); Eveland's observer is a lifecycle hook, not an instrumentation provider, and its delivery path is unchanged. The rest is developer UX: an `eve-tui/<version>` User-Agent token, rebuild progress in the `eve dev` status bar, and Slack approval-card fixes.

For the current latest line, Agent projects should refresh their lockfile and redeploy to receive `0.47.3`, even when a range such as `^0.47.0` already permits it. Custom NDJSON consumers must ignore blank lines and unknown event types (stream v24 adds `action.input.appended`) and must not treat a background-task receipt as terminal. Only enable remote principal forwarding after both deployments are upgraded and the receiver can name the exact trusted forwarder.

An npm publication alone does not widen the window. A new minor enters only after changelog and source review plus the complete compatibility matrix; removing an older minor is also an explicit product change.

## Enforcement points

Eveland fails closed when the dependency is missing, outside the window, or cannot be proven compatible during:

- source import and preflight
- build and restart
- cold activation (a Release whose build installed an out-of-window Eve version is refused at activation-request time — terminally, so a workflow run bound to it is dead-lettered once instead of retried after every cold start)
- Playground traffic
- public session create, continue, cancel, and stream
- public session reset
- every other public Agent Gateway request to the selected Deployment, including custom channel routes and webhooks (a dormant out-of-window Deployment answers 409 instead of being woken)
- schedule execution

The diagnostic asks the project owner to upgrade instead of guessing an older protocol. Review the release notes before upgrading either Eve or Eveland in production.
