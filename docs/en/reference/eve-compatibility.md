---
title: Eve compatibility
description: Understand Eveland's verified Eve version window and fail-closed policy.
---

Until Eve publishes a stable compatibility contract, Eveland supports only minor lines that have passed the complete compatibility matrix, and changes that window explicitly. The checked-in product contract supports `0.68.x` and `0.72.x`, verified at `0.68.0` and `0.72.1`. Eve 0.70 (retired on 2026-10-07 when 0.72 entered, five days after 0.70 itself had, before any Eveland release carried it), Eve 0.71 (skipped on 2026-10-07: 0.72.0 superseded it within four days, before any Eveland release carried it), Eve 0.69 (retired on 2026-10-02 when 0.70 entered, one day after 0.69 itself had, before any Eveland release carried it), Eve 0.62 (retired on 2026-10-02 when 0.69 entered), Eve 0.67 (retired on 2026-09-29 when 0.68 entered, three days after 0.67 itself had, before any Eveland release carried it), Eve 0.66 (retired on 2026-09-26 when 0.67 entered, two days after 0.66 itself had, before any Eveland release carried it), Eve 0.63, 0.64, and 0.65 (skipped on 2026-09-23 and 2026-09-24: 0.63.0 failed every session whose background subagent call met a hook subscribed to subagent events, which Eveland's own observer is, 0.64.0 shipped the fix, 0.65.0 superseded 0.64.1 within a day, and 0.66.0 superseded 0.65.0 within six hours, before any Eveland release carried any of them), Eve 0.58 (retired on 2026-09-23 when the window narrowed to the 0.62 floor), Eve 0.59, 0.60, and 0.61 (skipped on 2026-09-19: each was superseded within a day, before any Eveland release carried it), Eve 0.55 (retired on 2026-09-19 when 0.62 entered), Eve 0.56 and 0.57 (skipped on 2026-09-17: 0.58.0 superseded them before any Eveland release carried either), Eve 0.54 (retired on 2026-09-16 when 0.56 entered a window that was already two lines wide), Eve 0.52 and 0.53 (retired together on 2026-09-15), Eve 0.50 and 0.51 (retired together on 2026-09-12), Eve 0.49 (retired on 2026-09-07), Eve 0.48 (skipped when 0.49.0 superseded it on 2026-09-02, before any deployment ran on it), and Eve 0.47 and older are no longer accepted for import, build, restart, activation, Playground, Agent Gateway, or schedule execution.

The Eve dependency declarations a project's `package.json` may carry are: an exact patch inside a supported line, a `~`/`^` range anchored on a supported minor's patch, and the `0.68` / `0.68.x` / `0.68.*` and `0.72` / `0.72.x` / `0.72.*` forms. A missing Eve dependency, a broad cross-minor range, or any declaration that could resolve outside the window fails closed. The project Overview, Source, and Playground pages show the Eve dependency version of the current deployment's source revision alongside the platform requirement.

The window is a set of verified lines, not "everything at or above the floor": `0.72.x` entered on 2026-10-07, the day `0.72.1` was published, and `0.70.x` — which had entered on 2026-10-02, replacing `0.69.x` the day that line entered in place of the `0.62.x` floor — left with it before any Eveland release carried it; `0.71.x` was skipped. `0.68.x` stays because Eveland v0.60.0, the first release to carry a line newer than 0.62, ships it, so the window stays gapped and the SDK's peer floor stays at `>=0.68.0`. `0.69.x` through `0.71.x` sit inside the hull and are rejected with the same upgrade diagnostic as a retired line, as are `0.63.x` through `0.67.x`, which never reached a release (0.63.0 failed every session whose background subagent call met a hook subscribed to subagent events or `"*"`, which Eveland's observer is; 0.64.0 shipped the fix three days later; 0.65.0, 0.66.0, and 0.67.0 were each superseded within days). A Deployment whose Release was built on a retired line stops being servable as soon as Eveland carries the narrower window: the Agent Gateway answers it with 409, activation refuses it, and the platform settles the workflow runs still parked on it instead of retrying them; Eve cannot continue a session under a different Eve version, so a rebuild starts new sessions rather than resuming those. Between `0.68.0` and `0.72.1` the discovery manifest (v15), the routes Eveland forwards, and the sandbox provider API are unchanged; what moves is the message stream (v25 to v26), the session checkpoint (9 to 12), the compiled agent manifest (52 to 54), the bundled Workflow set (the 5.0.0 betas to the stable 5.0.1 release, with the same spec range), and above all delegation and human input — background tasks and the `subagent.*` events are gone, and a turn now holds open for its tasks, questions, approvals, and sign-ins (see the 0.72.x entry below). Every line in the window acknowledges messages with a delivery id, so every accepted Deployment is reachable from the Playground. The peer range is the union of the two contiguous runs (`>=0.68.0 <0.69.0 || >=0.72.0 <0.73.0`), never their hull, which would admit 0.69 through 0.71. `0.62.x`, `0.63.x` through `0.67.x`, `0.59.x` through `0.61.x`, and `0.48.x` — never verified, superseded by 0.49.0 within hours as 0.46, 0.43, and 0.40/0.41 were before it — stay below the floor together with `0.58.x`, `0.57.x`, `0.56.x`, `0.55.x`, `0.54.x`, `0.53.x`, `0.52.x`, `0.51.x`, `0.50.x`, `0.49.x`, `0.47.x`, and older; `0.73.x` is not admitted before it has passed the matrix.

The UI marks only the latest supported line, `0.72.x`, in green. Eve 0.68.x stays operational but appears in red with an upgrade reminder; unsupported versions also appear in red and remain blocked.

## Window baseline

Everything the platform once carried for older Eve lines is now the baseline of the whole window, and the pre-0.42 compatibility paths have been removed from Eveland entirely:

- Sessions are addressed only by their ID. Continuation tokens do not exist anywhere in the platform anymore: the token columns, the token-based reset translation, and the `POST /eve/v1/session/reset` token route are gone. Clear, compact, and reset live at `POST /eve/v1/session/:sessionId/{clear,compact,reset}`.
- `localDev()` is process-based and admits nothing under `eve start`; Agents on Eveland must authenticate with `evelandIdentity()`, `httpBasic()`, or OIDC.
- Channel message sends default to `turnPolicy: "steer"`; Eveland's injected scheduler adapter always asks for `"queue"` so a schedule never preempts a turn a person is waiting on.
- Eveland decides where every sandbox runs: it injects its managed bwrap sandbox (`@evelandhq/sandbox-bwrap`) into each Release. Every line in the window compiles sandbox modules that export a provider `environment` and a `defineSandbox()` selector (the shape 0.64 introduced), so Eveland keeps an authored module and redirects its `eve/sandbox` imports so that every built-in provider (`DefaultSandbox`, `DockerSandbox`, `VercelSandbox`, `MicrosandboxSandbox`, `JustBashSandbox`) builds the bwrap environment instead: the authored `prepare` and selector still run, and provider-specific options such as images and Dockerfiles are ignored; a slot the project left empty gets a generated module. `eve build` prepares every template and records the provider that prepared it, and Eveland refuses a Release in which any sandbox was prepared by another provider — an environment built in a helper file, a custom provider from `eve/sandbox/provider`, or a sandbox shipped by an Extension. The object-form `defineSandbox({ backend })` module Eveland generated for 0.62.x left with that line.
- Supported builds emit discovery manifest v15; the projector accepts nothing else (v14, emitted only by 0.45.0, left with the 0.45 line). v15 carries the `memories` list; 0.62.0 stopped writing its optional `instrumentation` module reference without a version bump when flat `agent/instrumentation.ts` stopped being discovered, and Eveland never read that field.
- The message stream protocol differs across this window: 0.68.x speaks **v25**, whose append events carry the delta alone (the v24 cumulative `messageSoFar` / `reasoningSoFar` snapshots and the UTF-16 `inputTextOffset` left with 0.49), and 0.72.x speaks **v26** (introduced by 0.69), which adds the task events (`task.started`, `task.settled`, `agent.started`, `turn.waiting`) and drops `subagent.*`. The 0.72 `eve/client` reads v21 through v26, so the Dashboard's Playground, built on it, reads both lines; a 0.68 client rejects v26, so a custom frontend must upgrade its `eve/client` together with an Agent that moves to 0.72; a 0.72 client keeps a held turn `streaming`, so a frontend must let people answer a pending question, approval, or sign-in while the turn runs, as Eveland's Playground does. Every response still carries the version in `x-eve-stream-version`, which Eveland's Playground and Agent Gateway forward verbatim; a custom NDJSON consumer should keep reading it rather than assuming the shape. Both lines carry the optional, separately negotiated transport lease 0.57 added on top of v25: a client that opts in with `?streamControlVersion=1` (the `eve/client` reader does so whenever reconnection is enabled and it reads from an absolute cursor) receives blank-line heartbeats every 10 seconds and, after 60 idle seconds, a `{"$eve":"stream.lease-ended","version":1}` control line that ends the response so the client reconnects from its cursor. The Agent Gateway forwards the query string verbatim and keeps its own 5-second heartbeat.
- Eve's implicit default model is `spacexai/grok-4.7` on 0.68.x and `openai/gpt-6-luna-fast` with high reasoning on 0.72.x; pin `model` explicitly to control provider, behavior, and cost.
- Durable delegation and invocation channels are baseline: remote child streams follow through the parent at `GET /eve/v1/session/:parentSessionId/subagents/:callId/:childSessionId/stream`, create-once `operationId` sessions, `POST /eve/v1/task-input/:token` callbacks (0.69 no longer exports the route constant but still serves the route for callers on older lines), and `mcpChannel()`'s durable agent tools all ride Eveland's durable Deployment routing boundary. 0.69 removed `POST /eve/v1/activity/:token` together with its activity collector; the Agent Gateway forwards paths transparently, so a 0.69 Agent answers that path with its own 404. Because every supported line speaks these routes, the Agent Gateway no longer maintains a per-operation Eve version floor — the window itself is the gate.
- Frontend `stop()` is gone; cancellation is the durable, hook-owned `cancel()` command. Eveland's Playground awaits it, including the interval before the first event identifies the durable turn, and keeps the stream attached through settlement.
- Workflow runs on storage spec v7, the sealed log: since `@evelandhq/workflow-world` 0.18.0 the World declares `mintedSpecVersion()` (7 by default, 6 for a Deployment that sets `WORKFLOW_SEALED_LOG=0`), and Releases built with 0.17.0 or earlier keep their spec-6 runs because the platform admits both generations. Every line's runtime accepts a World declaring 6 through 8 (0.68.0 bundles the `5.0.0-beta.57` Workflow set and 0.72.1 its stable `5.0.1` release, whose spec range is the same), and every line compares only the major and prerelease tag of the World's `@workflow/*` declaration (Eve's own bundled set moved to `5.0.0-beta.53/21/36/45` at 0.61.0, which is what 0.62.0 carries, to `5.0.0-beta.55/22/37/46` at 0.64.0, whose `@workflow/world` adds an optional `invoke` capability that Eveland's World does not declare, and to `5.0.0-beta.56/23/38/47` at 0.66.3, whose `@workflow/world` mints spec 8 — the hook force-claim reader contract, under which another run may take over a hook's token with `createHook({ experimental_force: true })` — to `5.0.0-beta.57/24/39/48` at 0.67.2, which leaves every spec constant where it was and is what 0.68.0 carries, and to the stable `5.0.1` release of the same family at 0.70.2, which leaves every spec constant where it was, only adds optional World members, and is what 0.72.1 carries; a stable version on either side matches any prerelease of its major), so one World serves both lines. The platform injects `@evelandhq/workflow-world@0.23.0` for every new build, whose `@workflow/world` beta.38 and `@workflow/world-local` beta.47 are behind what both lines bundle — the newer runtime asks for events with `resolveData: "skip-step-inputs"`, which this World answers exactly as it answers `"all"` — while it keeps declaring spec 7 (`Math.min(mintedSpecVersion(), 7)`) — a cap set while 0.62.0, whose runtime refused a World above 7 at startup, was in the window, and which every remaining line still reads — and never takes a hook token over — a forced creation is answered with an ordinary `hook_conflict`, so no run it stamps is ever stranded; and which delivers held dispatches over Node's core HTTP client so that a step running longer than five minutes is no longer cut off and redelivered by the 300-second deadline of the global `fetch`, addresses a cross-deployment `start()` to the Deployment it names instead of the one that enqueued it, and (since 0.21.0) commits a run and its `run_created` event in one transaction; `@workflow/world-postgres@5.0.0-beta.34` exists only in historical Releases and is never selected for a new build. Older spec-v5 worlds fail the startup guard. The shared World also bounds physical stream storage with snapshot stripping, block packing, checkpoints, and deadline-driven retention.
- MCP channels default to `/eve/v1/mcp` and may declare another `route`; Eveland's path-transparent Agent Gateway preserves either path and the corresponding OAuth protected-resource metadata route.
- Durable tools are declared with `defineWorkflowTool` from `eve/tools` and delegate with `ctx.agent()` — on 0.68.x `ctx.agent(target, input)` resolves the child's result, and from 0.69 `ctx.agent(name)` returns a session whose `send(message, { outputSchema })` answers with a response whose `result()` resolves the turn; Eve derives the replay-stable invocation identity itself; workflow tools on the parent flow through one ordered inbox where a retried dispatch may start another run, and `defaultTools: false` opts an Agent out of Eve's optional default tools. `experimental.workflow.retention: 0` and `experimental.workflow.modelCallsPerStep` are opt-in Agent options across the window: the retention preference is recorded on the run as the reserved `$retention` attribute, which Eveland's shared World stores but does not enforce, and a larger step batch widens the replay unit after an interruption.
- The `task_update` tool and its child-to-parent progress callbacks are gone across the window. On 0.68.x follow a background task through the child session's stream and expect overlapping background-task results to reach the parent together across launch turns; from 0.69 there are no background tasks — a call holds its turn until `task.settled` (see the 0.72.x entry).
- The OpenTelemetry agent trace schema is 4 across the window: every activation is an `invoke_agent` span grouped by `gen_ai.conversation.id`, model input is recorded once as `gen_ai.input.messages`, and memory recall/capture emit their own spans and `memory.operation.*` hook events. Eveland's observer and collector mappings key on none of the pre-4 names, but a dashboard built on an Agent's own `otel()` export must target schema 4.
- Extension contracts drop versions as Eve reworks them, and 0.72.x refuses every one a 0.68.x build emits for the families 0.69 changed: 0.69 dropped `tool` 58–62, `dynamicTool` 56–59, `channel` 33–35, `schedule` 16–17, `subagent` 21–22, `connection` 28–31, `hook` 28–30 (and the long-deprecated 10–19), `dynamicSkill` 23–24, and `dynamicInstructions` 24–25 when it removed background tasks and moved extension configuration and durable state onto each logical mount. 0.72.1 is at `tool` 76, `dynamicTool` 72, `channel` 48, `schedule` 27, `subagent` 30, `connection` 39, `hook` 38, `dynamicSkill` 32, and `dynamicInstructions` 33 (0.72 also dropped `tool` 54–55 and 63–75 and `dynamicTool` 71 when `evaluate` became `decide`, so a tool Extension built on 0.70 or 0.71 must be rebuilt too); `extension` 1, `skill` 2, `instructions` 2, `config` 1, and `state` 9 did not move. A prebuilt Extension must therefore be rebuilt against the line the project builds on; Extensions Eveland injects itself are compiled from source and unaffected. Eve's CLI reports usage to Vercel unless `EVE_TELEMETRY_DISABLED` is set; Eveland sets it for every build and deployment it runs.
- Extensions may provide channels, schedules, and namespaced subagents; their full platform scheduling and observer integration is delivered as a separate compatibility follow-up.
- `chatgpt()` is stable with Codex-owned authentication — but ChatGPT subscription models are local-only by design: there is no Codex sign-in inside an Eveland deployment, so an Agent pinned to `chatgpt()` deploys and then fails at run time. Use an AI Gateway or server-authenticated model for deployed Agents.
- `glob` and `grep` are not in the default Agent tool set; an Agent that relies on them must export them from the corresponding tool files by re-exporting the provided definitions from `eve/tools/glob` / `eve/tools/grep` (the `defineGlobTool()` / `defineGrepTool()` factories left the window with 0.44).
- A child agent can share the dispatching parent's live sandbox by exporting `defineParentSandbox()`; such a child cannot also declare managed workspace or skill resources, and Eveland's platform sandbox applies to the parent as usual.

## Supported version lines

- **Eve 0.68.x (verified at `0.68.0`)**: Sandboxes are provider environments (since 0.64). A sandbox module exports an `environment` built from a provider (`DefaultSandbox.environment()` from `eve/sandbox`, or `DockerSandbox`, `VercelSandbox`, `MicrosandboxSandbox`, and `JustBashSandbox` from their `eve/sandbox/*` entry points) and a `defineSandbox()` selector that opens it; object-form `defineSandbox({ backend, bootstrap, onSession })`, `defaultBackend`, and `revalidationKey` are gone. Setup every sandbox inherits moves into the environment's `prepare`, which `eve build` runs once while it prepares the template — on Eveland inside bwrap at build time — and per-session setup moves into the selector, after `open()`. A module in one shape does not compile on the other, so a project coming from 0.62 or older rewrites its sandbox module before it can deploy. 0.63 moved durable background work onto workflow tools: `defineTool({ execution: "background" })`, background dynamic tools, `TaskExec`, and `postMessage` are gone in favor of `defineWorkflowTool`, the unstamped `taskRunWorkflow` run went with them, and each background cohort's completed, failed, and cancelled outcomes reach the parent in one automatic report. A background subagent call now returns its receipt only as the call's `action.result`, and `subagent.completed` fires once, after the parent records the child's actual result; Eveland's observer keeps the call's span open from the receipt until then, or until the child session ends, so the child's spans stay under it. Message sends accept `taskDeliveryPolicy: "auto" | "cohort"`: channel sessions default to `"auto"`, which may report independently useful background results early, and Eve's own schedules to `"cohort"`; Eveland's scheduler asks for `"cohort"`, so an Eveland schedule reports like an Eve one. `/eve/v1/info` answers in version 5, with provider-based sandbox fields that Eveland does not read. The implicit default model is `spacexai/grok-4.7`. 0.65 reworks the built-in tool set: the `todo` tool and its `eve/tools/todo` entry point are gone, and an `agent/tools/todo.ts` — even one that only exports `disableTool()` — now fails the build, which on Eveland surfaces as a failed Release build. `ask_question` left the default tool set and became an opt-in workflow tool: add it with `eve add tool/ask_question` (an `agent/tools/ask_question.ts` that default-exports `askQuestion()` from `eve/tools/ask_question`); a file that disables it fails the build the same way, and an Agent that relied on the default tool simply loses it and asks in its reply text instead. The model now asks one `question` with up to three `{ label, description }` options, the user can always answer in free text, and the tool returns `{ status: "answered", answer }`, `{ status: "dismissed" }` when the user moved on, or `{ status: "unavailable" }` when the session cannot request input. `ctx.ask()` resolves to the same `status` shapes (check `status` before reading `optionId`), a plain-text message answers the only pending question when it matches an option or free text is allowed, and `dismissible: true` resolves it as dismissed on an unrelated message; a request's `requestId` is no longer its tool call ID, so relate them through `action.callId`. Eveland's Playground renders and answers these questions as before. Compaction no longer resets `write_file` read tracking, and `eve dev` mounts development-only extensions (the local self-modification subagent) unless `--no-default-extensions` is passed; production builds, which are what Eveland runs, do not. Consecutive deployment handoffs now keep a session on its original stream, but handoff stays inert on Eveland. Eve's bundled Workflow set moved at 0.64.0, 0.66.3, and 0.67.2 (see the window baseline). 0.66 removes `ctx.getSkill()` and the `SkillHandle` and `SkillFile` types from `eve/skills` — the model still reads a skill's supporting files with its sandbox tools, and tool or hook code that needs them imports from a module in `lib/` instead — and dynamic skills no longer start a sandbox just to announce or load their instructions; existing extension builds keep loading unless they called `ctx.getSkill()`. `setNetworkPolicy` left the common `SandboxSession` type: pass the configured environment to `ctx.getSandbox(environment)` to keep that provider's session capabilities on the handle (Eveland's bwrap environment still offers it). Tool schemas reach the model as JSON Schema, MCP and other JSON Schema tools are advertised exactly as published and validated with a standard JSON Schema validator, the `*_INPUT_SCHEMA` and `*_OUTPUT_SCHEMA` constants from `eve/tools/*` are JSON-Schema-backed Standard Schemas rather than Zod objects, and Eve ships one private copy of Zod, so a project that installs its own Zod version no longer breaks MCP or file-memory tool turns; `eve/client` no longer exports its Zod schemas (`inputRequestSchema` and its siblings — use the exported types with `isInputRequest`, `isInputResponse`, and `parseInputResponse`), none of which Eveland's Playground imported. `subagent.called` and `subagent.completed` hooks can call `ctx.getSandbox()` for the parent session and keep their sandbox changes for the parent's next turn, and the new built-in `eve/extensions/code` extension (`apply_patch`, `gh`, `grep`, computer use, coding skills, and a read-only worker subagent) uses the application's own sandbox, so on Eveland it runs inside bwrap. Compaction summaries leave temperature at the provider's default. 0.66.1 adds `session.streamSubagent(called)` to `eve/client` for following a delegated child's stream, hands `eveChannel({ trustedForwarders })` the asserted principal as a second argument (Eveland does not use trusted forwarders), keeps a delegated task open while its yielded child still has background work running, and has `eve build` build mounted, source-backed workspace extensions (packages declaring `eve.extension.source` and `eve.extension.dist`) before compiling the agent, so a build no longer depends on the package manager having run their `prepare` script — on Eveland that build now happens inside the build sandbox. No wire surface changed between 0.66.0 and 0.66.1. 0.66.2 ignores `*.test.*` and `*.spec.*` modules and `__tests__/` directories during agent discovery, so a project's colocated tests no longer register as agent files. 0.66.3 moves the bundled Workflow set to `5.0.0-beta.56/23/38/47`, whose runtime reads storage spec 6 through 8 (see the window baseline for why Eveland's World keeps stamping 7), marks new session handoffs as protocol version 2 while reading unversioned ones as version 1, and lets `slackChannel` and `callSlackApi` take an `api` option that points Slack Web API calls at another host. 0.67 changes the session lifecycle: the `conversation` / `task` run mode is gone, so every session — a schedule's, an MCP `agent_start` invocation's, a delegated child's — parks after each turn instead of ending, and only its `limits.sessionTimeoutMs` (seven days by default) ends it; `mode` left `ChannelAddress`, the Chat SDK `send(...)` options, and the audience and trace-policy inputs, and the eve HTTP channel ignores a `mode` field on session creation. A channel send now always grants the request-input capability, so a session a channel starts parks on a tool approval or a `ctx.ask()` until someone answers, where a task-mode session used to fail fast; a schedule that reaches a tool approval therefore sits parked rather than failing — keep schedules on tools that need no approval, or answer the question from the Playground. Eve's own markdown schedules have no channel and still fail fast. `outputSchema` is removed from `defineAgent`, `defineRemoteAgent`, `defineWorkspaceAgent`, dynamic subagent configs, agent info, the model-facing subagent and `agentRouter()` tool inputs, MCP `agent_start`, and the channel `from(address).send()` / `respond()` options: request structured output per turn through the session API or `ctx.agent()` instead. The default `eve/client` reducer keeps approval, question, and session-limit prompts pending until the server confirms the answer, so a frontend disables its response controls while the store is `submitted`, `streaming`, or `resuming` — Eveland's Playground already does. `/eve/v1/info` still answers in version 5 but lists only the priority-tier indicator among a model provider's options, so credentials stored under an unexpected key cannot leak there. Instrumentation setup now completes before the server's dependencies load, so OpenTelemetry can instrument packages such as `pg`; MCP connection calls carry OpenTelemetry context in their metadata and MCP semantic attributes on their tool traces; parent stream-event hooks run after proxied input requests and authorization events are published and receive the published event ID; `step.completed` carries a `stepIndex`; a parent's steering text no longer resolves a delegated child's pending `ctx.ask()`; and turn-scoped dynamic connections are restored before an approval response is authorized, including after a cold start. On the CLI, `eve remote connect <url>` and `eve remote invoke <url>` replace `eve dev <url>` and `eve invoke`, and `eve set model [model] [--reasoning <effort>]` replaces `eve set --model` and `eve set --reasoning`; `eve dev` now starts only local development. Extension contracts stay additive (`tool` 58, `dynamicTool` 56, `channel` 33, `schedule` 16, `subagent` 21, `connection` 28, `hook` 28, `dynamicSkill` 23, `dynamicInstructions` 24), and the compiled agent manifest moves to version 52. 0.67.1 sends the conversation ID as the AI Gateway session ID on model and compaction calls unless one is configured explicitly, and fixes `useEveAgent({ resume: true })` crashing with React error #185 when a saved session replays more than about fifty events — the store now publishes once after catch-up — which Eveland's Playground, which resumes sessions, benefits from directly. 0.67.2 stops parallel tool calls from subagents that share a sandbox from racing to start it, no longer logs a cancelled turn's running tool as a failed tool execution, and moves the bundled Workflow set to `5.0.0-beta.57/24/39/48`. 0.68 changes what a failing hook does: a stream-event hook that throws no longer fails the turn or the session — Eve logs the failure with the hook and event identifiers, runs the remaining subscribers, and carries on, including for `turn.started` and `step.started` hooks, which used to end the turn with `EVENT_HANDLER_FAILED` — and a hook can call `ctx.cancel()` to cancel the running turn once the event's remaining subscribers have run, which settles like `session.cancel()`. Provider-call retries are recorded as distinct model-call spans and failed attempts are terminalized; usage on Eveland still comes from `step.completed`, so a retry is not counted twice. Turn-scoped dynamic tools restore their durable callbacks when a turn resumes in another process, tools resolved through `defineDynamic` carry their label presentation on `actions.requested` and `action.result` like static tools, MCP tools found through `connection_search` hand the model only their result's `content`, and an answered workflow-tool `ctx.ask()` carries the authenticated responder's identity (`POST /eve/v1/task-input/:token` accepts an optional `responder`). Computer use moves out of `eve/extensions/code` into its own built-in extension, `eve/computer-use` (tool name `computer-use__computer_use` when mounted as `agent/extensions/computer-use.ts`); it declares no sandbox of its own, so on Eveland it runs inside bwrap, and the old `eve/extensions/code/sandbox` and `eve/extensions/code/tools` exports still work but are deprecated. Extension contracts stay additive (`tool` 59, `channel` 34, `hook` 29), and the session checkpoint and compiled manifest versions do not move.
- **Eve 0.72.x (recommended, verified at `0.72.1`)**: 0.69 removed background tasks, and 0.70 and 0.72 keep that model. Every workflow tool call and every agent call holds its turn until it settles: a `task()` workflow tool or an agent tool runs each call as a task whose call returns a plain-text receipt (`Started task …`), the result reaches the model later in a `<task_result>` message, the model waits with `task_wait` or stops a task with `task_cancel`, and a turn cannot end while its tasks work. A `serve(receive, ctx)` workflow tool runs one resumable task the model can call again with its `taskId`; every agent tool is now built that way, so the model continues or corrects a subagent by passing `taskId` (replacing `agentId`). `defineWorkflowTool` rejects `execution`, and `taskDeliveryPolicy`, `session.cancel({ tasks })`, task notifications, `dismissible`, and the `<eve-empty-delivery/>` marker are gone; Eveland's scheduler stops sending `taskDeliveryPolicy` to a Release on 0.69 or later. The `subagent.called`, `subagent.started`, `subagent.event`, and `subagent.completed` events and their hooks are removed in favour of `task.started` (`kind: "agent"` or `"tool"`), `task.settled` (its status, output or error, and `cancel.reason`), and `agent.started` (the child's `sessionId`, `name`, and `taskId`, and `remote.url` for a remote agent); `session.streamSubagent(called)` became `session.agent(started).stream()`. Eveland's observer and session projection read both generations: an agent call's span stays open from its receipt to `task.settled` and records the reply, a continued task's later child turns nest under the call serving them, the child SessionNode — an unresolved remote one included — is linked from `agent.started`, and the session replay shows the settled reply instead of the receipt. A question or sign-in raised inside a running call — a workflow tool's `ctx.ask()`, `ask_question`, or a subagent's question — no longer ends the turn: the stream emits `input.requested` (or `authorization.required`) and then `turn.waiting`, and the turn resumes under the same `turnId` once it is answered, with `input.resolved` marking the answer. Eveland moves the session back to running on `input.resolved` and parks a scheduled run on a `turn.waiting` under a pending question, as it does on `session.waiting`. In a root session the text the model writes before it waits on its tasks completes as an ordinary message right away; Eve keeps a single final reply only for child sessions and its own scheduler's sessions, and Eveland dispatches schedules through its own channel, so a scheduled turn that delegates can post that early text too. `ctx.agent(name)` returns a session (`send(message, { outputSchema, signal })`, then `result()`); `ctx.agent(name, { message, agentId })` is removed, and remote agents now check a protocol version (a 0.69 remote agent still serves callers on 0.66 through 0.68). Connection tools no longer enter the model's tool list: the model finds them with `connection_search` and calls them through the new `connection_execute`, which returns MCP `structuredContent` or text, and the `eve/tools/connection_search` export is removed. Approval response policies run for Cancel as well as Approve and read the responder from `response.principal`. Extension configuration and durable state belong to each logical mount, and every changed extension contract family dropped its 0.68 versions (see the window baseline), so prebuilt Extensions must be rebuilt. The session checkpoint moved to 10 at 0.69 and 11 at 0.70, and Eve rejects a handoff across either boundary in both directions; handoff stays inert on Eveland, which binds every session to its Deployment. Tools can end a turn without a reply (`endsTurn: true`, or the opt-in `no_reply` tool from `eve add tool/no_reply`). `eve/server` adds an in-process `sessions.attach(sessionId).stream()`, `eve/schedules` exports `isScheduleAuth(auth)`, which recognizes the app principal Eveland's scheduler sends, and the implicit default model is `openai/gpt-6-luna-fast`. Delegated usage now counts toward the parent's session budgets; Eveland still takes usage from each model step's own `step.completed`, so nothing is counted twice. Slack channels replace `slackChannel({ events })` with `renderers`, the Chat SDK bridge's `send()` takes `(message, { context, thread })` with a separate `respond()`, and sign-in challenges and approval feedback go privately to the Slack user behind the event's principal. 0.70 extends the held turn to tool approvals and connection sign-ins: instead of `turn.completed` and `session.waiting`, the stream emits `turn.waiting`, which now says what it waits `on` (`"input"` when a person must act, `"tasks"` when the turn waits on its own work), and the same turn resumes once the person acts; a message from that person steers the turn and cancels the pending approval or sign-in, and cancelling the turn withdraws both. Eveland counts a pending sign-in as waiting on a person like an approval — the session shows as waiting for review until `authorization.completed`, and a scheduled run that holds for one parks — and the Playground lets people answer while a turn is held. A plain `connection_search` no longer asks the user to sign in: unauthorized connections appear under `unavailable` with `requiresSignIn: true`, and the model signs in with `connection_search({ connection, signIn: true })`. `session.waiting`, `turn.waiting`, `session.completed`, and `session.failed` carry the session's running `usage` including what delegated agents spent; Eveland keeps taking usage from each model step's own `step.completed`, so nothing is counted twice. The frontend hooks and `EveAgentStore` share one conversation client: the default `useEveAgent` data is a `ConversationState` (messages plus turns, input requests, tasks, and agent sessions), and a held turn stays `streaming` with `turns[turnId].waiting` set. The first local subagent turn now joins its caller's trace; Slack identifies a person by the installation workspace (`slack:<team>:<user>`), so user-scoped connections ask Slack Connect and Enterprise Grid users to sign in once more, and Slack's `onMessage` receives only new messages. 0.71 and 0.72 keep the message stream at v26 — `input.requested` only gains an optional `callId` naming the call a relayed request serves — and leave the discovery manifest, the compiled manifest (54), the routes, and the sandbox provider API where 0.70 left them; they move the session checkpoint to 12 (handoff stays inert on Eveland) and bundle the stable Workflow SDK 5.0.1 set instead of the 5.0.0 betas (see the window baseline). The `bash` tool no longer blocks on a command still running after 30 seconds: it returns `status: "running"` with the process group's `pid` and an `outputDirectory`, and `exitCode` is present only on `completed` results; inside Eveland's bwrap sandbox each command runs in its own namespace, so such a command keeps blocking until it finishes, as on 0.70. Approvals without a `response` policy now answer only to the principal whose turn requested the call, and an approval granted by someone else runs only that call as the approver: a scheduled turn runs as the app principal, so an approval it raises cannot be granted from the Playground, and in a shared session only the member whose turn asked can approve. Answering some of several pending questions parks the turn again with `turn.waiting` (`on: "input"`), which Eveland projects as waiting for review; a plain-text answer is recorded as `message.received` before its `input.resolved`; pending input is withdrawn when a cancel, a context clear, or a finished workflow removes its owner, and a withdrawn approval renders as denied. The Playground shows every question a tool call asks at once and keeps answer buttons live only for requests that are still open. After compaction an idle session moves to a fresh workflow run on the same Deployment, so a long session stops growing one event log; it keeps its ID, stream, and Deployment binding. MCP connections that declare `auth` but hold no token connect anonymously and ask the user to sign in only when the server answers `401` or a `mcp/www_authenticate` challenge. `evaluate` from `eve/ai` is now `decide` (AI SDK 7.0.128), which drops the older `tool` and `dynamicTool` contract versions (see the window baseline); `defineInstrumentation` replaces `action.*` handlers with `tool.call.*` and exports one `execute_tool` span per tool call, which leaves Eveland's observer, built on stream events, unaffected. Channel route handlers gain `describe()` and `invokeTool(name, input, { auth })`, `mcpChannel` can publish the Agent's own tools with `tools: true`, frontmatter parses with js-yaml 4 and accepts only `---` or `---yaml` fences, and files people send reach the agent on more channels. For the current latest line, Agent projects should refresh their lockfile and redeploy to receive `0.72.1`.

An npm publication alone does not widen the window. A new minor enters only after changelog and source review plus the complete compatibility matrix; removing an older minor is also an explicit product change.

## Enforcement points

Eveland fails closed when the dependency is missing, outside the window, or cannot be proven compatible during:

- source import and preflight
- build and restart
- cold activation (a Release whose build installed an out-of-window Eve version is refused at activation-request time — terminally, so a workflow run bound to it is dead-lettered once instead of retried after every cold start)
- Playground traffic
- public session create, continue, cancel, and stream
- public session reset
- every other public Agent Gateway request to the selected Deployment, including custom channel routes and webhooks (a dormant out-of-window Deployment answers 409 instead of being woken)
- schedule execution

The diagnostic asks the project owner to upgrade instead of guessing an older protocol. Review the release notes before upgrading either Eve or Eveland in production.
