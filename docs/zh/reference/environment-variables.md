title: 环境变量
description: 查阅平台读取的全部环境变量，含默认值与读取位置。
---

本页是 **eveland 平台**（API、Worker、Gateway、DB 与托管 OpenTelemetry
Collector）读取的全部环境变量参考。每个变量都列出默认值与读取位置，运维者可以据此
判断哪些是可选项、值在哪里生效。

**Test-only** 变量——只被测试/集成 Harness 读取——明确**不在范围内**，统一列在
页面末尾，避免与平台配置混淆。

除非另有说明，变量都在进程启动时经 `process.env` 读取。"生产必填"表示缺失时进程
抛错或部署被阻断。

## Storage

| 变量                                   | 用途                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | 默认值                                                                                                       | 读取位置                                                                                                                                                                            |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`                         | eveland 自己的平台 Postgres（Project、Deployment、Session、Secret、Log 等）。                                                                                                                                                                                                                                                                                                                                                                                                                        | —（必填）                                                                                                    | DB（`packages/db/src/client.ts`）                                                                                                                                                   |
| `DATABASE_POOL_SIZE`                   | pg 连接池最大连接数。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | `10`                                                                                                         | `packages/db/src/client.ts`                                                                                                                                                         |
| `WORKFLOW_POSTGRES_URL`                | **Legacy** 按项目 Workflow Postgres 基础 URL。只在共享 World 之前的 Project 仍在删除时需要：它让 Worker 枚举并删除派生的 `eveland_wf_<project>_<digest>` 数据库（因此基础 URL 的 Role 需要 `CREATEDB`）。新构建从不使用它，生产不必填，External-only 安装从不设置。Reserved：Project Secrets 不能覆盖它。当没有 Legacy-attested Deployment 残留时即可安全移除；见[升级](/zh/docs/operations/upgrades)。                                                                                              | —                                                                                                            | Worker（`apps/worker/src/jobs/process-support.ts`、`apps/worker/src/runtime/workflow-world-bootstrap.ts`）                                                                          |
| `WORKFLOW_POSTGRES_BOOTSTRAP_URL`      | 可选的、Worker 可达的 Legacy 基础数据库地址。当面向 Deployment 的 URL 是容器专用时，Worker 用它创建、初始化、枚举和删除派生的按项目数据库；它从不在基础数据库本身安装 Workflow Schema。当没有 Legacy-attested Deployment 残留时即可安全移除；见[升级](/zh/docs/operations/upgrades)。                                                                                                                                                                                                                | 当 `WORKFLOW_POSTGRES_URL` 使用 `host.docker.internal` 时匹配 `DATABASE_URL`；否则为 `WORKFLOW_POSTGRES_URL` | Worker（`apps/worker/src/runtime/workflow-world-bootstrap.ts`、`apps/worker/src/runtime/workflow-world-reaper.ts`）                                                                 |

| `EVELAND_WORKFLOW_WORLD_URL`           | 支撑 `@evelandhq/workflow-world`（平台的多租户 Workflow World）的共享 Postgres 数据库。每个新构建都会烘焙这个 World，因此生产 Worker 缺少该 URL 时启动 Fail Closed。API 从它派生 World 的 Cluster Identity，并拒绝为注册到其他 Cluster 的 Dispatcher 执行 Workflow-step Activation。Deployment Retention 保护带非终态 Run 的 Deployment（被未解决的 Dispatch Dead Letter 隔离的除外）；Worker 启动或 Tenant Provisioning 会在 Dispatcher 或 Deployment 使用之前自动应用全部待执行 Schema Migration。 | —（生产必填）                                                                                                | API 与 Worker（`packages/core/src/workflow-world-url.ts`、`packages/db/src/workflow-world-identity.ts`、`apps/worker/src/runtime/eveland-workflow-world-bootstrap.ts`）、Dispatcher |
| `EVELAND_WORKFLOW_WORLD_BOOTSTRAP_URL` | 同一共享 Workflow Database 的宿主机可达 URL。当 Deployment 访问 Postgres 的主机名与平台不同（如 Docker Desktop 下的 `host.docker.internal`）时设置。                                                                                                                                                                                                                                                                                                                                                 | `EVELAND_WORKFLOW_WORLD_URL`                                                                                 | API 与 Worker（`packages/core/src/workflow-world-url.ts`）、Dispatcher                                                                                                              |

> **`EVELAND_WORKFLOW_WORLD_URL`（以及 Legacy 安装上的
> `WORKFLOW_POSTGRES_URL`）必须使用容器可达的主机名**（如
> `host.docker.internal`），不能用 `localhost`，因为 Agent 容器从容器内部访问宿主机
> 数据库。可选的 Bootstrap URL 则可以使用 `localhost` 或 Compose Service 名，因为
> 只有平台自己的进程读取它们。对常见的单机部署，Worker 还会识别只有主机名不同的
> `DATABASE_URL`，用这个可达 URL 管理 Legacy 派生项目数据库。

## Encryption

| 变量             | 用途                                                                                                                                                                                                                                                                                               | 默认值                                        | 读取位置     |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- | ------------ |
| `APP_SECRET_KEY` | 对称密钥（aes-256-gcm），用于 Project Secret、个人 Git Host 凭据、外部 Observability Destination 以及派生的 Agent 遥测签名密钥。API 写入时加密；Worker 只在所属 Runtime 边界解密。轮换有意要求重新部署全部 Agent Deployment，使其签名的遥测凭据匹配新的 API 密钥。由 `assertValidSecretKey` 校验。 | 仅限开发的 `eveland-dev-secret-key-000000000` | API + Worker |

> 处于无保护状态。

## Agent-user Identity

| 变量                                   | 用途                                                                                                                                                                                                                                                                                                                                 | 默认值                                                   | 读取位置                                   |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------- | ------------------------------------------ |
| `EVELAND_IDENTITY_ISSUER`              | 嵌入 Eveland Caller Token 的稳定公开 Issuer。必须与每个消费方 Chat 服务和 Agent Verifier 配置的 Issuer 一致。`http://localhost:4000` 默认值只在非生产环境生效。生产环境未设置时会在 Settings > About **报告为缺失**：Worker 只有拿到 Issuer 才会注入 Deployment，缺少它的 Agent 会拒绝所有 Caller Token 且无从诊断。启动不会被阻断。 | `http://localhost:4000`                                  | API + Worker                               |
| `EVELAND_IDENTITY_ALLOWED_ORIGINS`     | 逗号分隔的精确浏览器 Origin，允许读取 Identity Session 状态、请求 Caller Token 与登出。公开 Agent Catalog 不依赖此 Allowlist。不支持通配符。                                                                                                                                                                                         | `http://localhost:3010`                                  | API                                        |
| `EVELAND_IDENTITY_JWKS_URL`            | 注入每个 Deployment 的 Agent 可达公钥 URL。它可以使用私有/回环地址，只要 `EVELAND_IDENTITY_ISSUER` 保持稳定公开 Issuer。                                                                                                                                                                                                             | `http://host.docker.internal:4000/.well-known/jwks.json` | Worker                                     |
| `EVELAND_PROJECT_ID`                   | Worker 注入每个 Agent Deployment 的 Audience/Project 绑定。Project 与 Shared Agent Environment 的值不能覆盖它。                                                                                                                                                                                                                      | 当前 Project ID                                          | 部署的 Agent                               |
| `EVELAND_IDENTITY_OIDC_ALLOW_INSECURE` | 设为 `1` 允许平台 OIDC Identity Provider 访问 `http://` 或私网 Issuer。为对回环 IdP 的本地集成测试而存在；生产环境绝不设置——它会关闭 Identity Broker 每次 OIDC 请求的 HTTPS 与私网地址防护。                                                                                                                                         | 未设置（仅 https Issuer）                                | API                                        |
| `EVELAND_ALLOWED_REALM_IDS`            | SDK 侧 Realm Allowlist：逗号分隔的 Realm ID（`irlm_...`），限定 Agent 的 `evelandIdentity()` 接受哪些 Realm 的用户。Identity Broker 认证调用者，但不决定哪个 Realm 可以访问哪个 Agent，因此不设置时接受任何已启用 Realm 的 Token；设置后其他 Realm 的 Token 会作为未认证拒绝。显式的 `allowedRealms` 选项优先于它。                  | 未设置（任何已启用 Realm）                               | 部署的 Agent（`packages/sdk/src/auth.ts`） |

`eveland_identity` Cookie 与 Better Auth 分离，作用域为 `/identity`；
`/agent-catalog` 是公开的、与 Identity 无关的投影。Caller Token 为 ES256、短时效，
把一个 Principal 认证到一个 Project Audience；业务授权仍由 Agent 负责。浏览器返回
Origin 在 System > Identity 中注册；环境的 CORS 配置不会创建或扩大该 Redirect
Allowlist。

即使旧的本地 `.env` 不含这些变量，Native 开发也会提供表中默认值。API 与 Worker 的
开发 Watcher 同时监听共享 `.env`。注入的 Issuer 或 JWKS URL 变化时，Worker 记录一份
配置 Fingerprint，并为每个存活 Deployment 排队一次定向重启，使运行中的 Agent 不会
保留过期的 Verifier 设置。生产环境不提供 localhost Fallback，必须显式配置。

Internal-provider 里程碑使用 Same-site 浏览器拓扑。Eveland Identity 与 Chat Origin
必须共享一个 Schemeful Site（通常为同级 HTTPS 子域），因为 Identity Cookie 是
`SameSite=Lax`。仅有精确 CORS 配置并不能允许来自无关 Site 的携带凭据请求。

## Workflow Dispatcher

Dispatcher（`apps/workflow-dispatcher`，`@evelandhq/workflow-world` 内 Dispatcher 的薄启动器）从共享 Workflow Database Claim Durable Workflow Job，并把每个 Step POST 回所属 Agent Deployment，若其已被 Idle-reaped 则先激活。它读取上文的 `EVELAND_WORKFLOW_WORLD_URL` / `EVELAND_WORKFLOW_WORLD_BOOTSTRAP_URL`，外加下表变量。

它目前每个共享数据库单实例，并持有一个生命周期 PostgreSQL Advisory Lock。首次从未持有该锁的 Dispatcher 版本升级时，先停止旧进程再启动新进程；第二个参与的 Dispatcher 会 Fail Closed。

| 变量                                                  | 用途                                                                                                                                                                                                                      | 默认值                                                | 读取位置                    |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- | --------------------------- |
| `WORKFLOW_DISPATCHER_ACTIVATION_API_URL`              | Dispatcher 激活 Deployment 时使用的 Control API Base URL，与 Agent Gateway 冷启动完全一致。                                                                                                                               | —                                                     | `@evelandhq/workflow-world` |
| `WORKFLOW_DISPATCHER_ACTIVATION_TOKEN`                | `/internal/runtime/activations` 的 Bearer Token。从不交给 Deployment——向 Executor 的 Dispatch 改用 `EVELAND_SCHEDULER_RUNTIME_SECRET` 认证。                                                                              | _（仅显式 `NODE_ENV=development` 下有开发 Fallback）_ | `@evelandhq/workflow-world` |
| `WORKFLOW_DISPATCHER_POOL_SIZE`                       | 共享 Postgres 连接池大小。一个连接用于生命周期 Ownership，一个用于 Graphile LISTEN；其余服务 Claim/Complete 往返。等待 Executor 的挂起 Dispatch 不占用连接，因此按 Dispatch **速率**而非并发定容——常用范围 6–16。最小 4。 | `10`                                                  | `@evelandhq/workflow-world` |

| `WORKFLOW_DISPATCHER_MAINTENANCE_MAX_BATCHES`         | 一次维护中 Stream 与 Workflow-run 删除批次的上限。                                                                                                                                                                        | `20`                                                  | `@evelandhq/workflow-world` |
