---
title: 环境变量
description: 查阅平台读取的全部环境变量，含默认值与读取位置。
---

本页是 **eveland 平台**（API、Worker、Gateway、DB 与托管 OpenTelemetry
Collector）读取的全部环境变量参考。每个变量都列出默认值与读取位置，运维者可以据此
判断哪些是可选项、值在哪里生效。

**Test-only** 变量——只被测试/集成 Harness 读取——明确**不在范围内**，统一列在
页面末尾，避免与平台配置混淆。

除非另有说明，变量都在进程启动时经 `process.env` 读取。"生产必填"表示缺失时进程
抛错或部署被阻断。

在已安装的主机上，配置位于 `/opt/eveland/etc/eveland.env`，由 `eveland-ctl` 在首次启动时
生成，并拆分为各 systemd 单元的服务级环境文件。不要把开发环境的 Fallback 带进生产。
管理员可以在 **Settings → About** 对比各组件按白名单展示的生效配置，Secret 值始终脱敏。
Agent 采集、隐私与外部遥测目的地属于 System 设置，不是环境变量。

## Storage

| 变量                              | 用途                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | 默认值                        | 读取位置                                                                                                                                                                    |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`                    | eveland 自己的平台 Postgres（Project、Deployment、Session、Secret、Log 等）。                                                                                                                                                                                                                                                                                                                                                                                                                        | —（必填）                     | DB（`packages/db/src/client.ts`）                                                                                                                                           |
| `DATABASE_POOL_SIZE`              | pg 连接池最大连接数。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | `10`                          | `packages/db/src/client.ts`                                                                                                                                                 |
| `WORKFLOW_POSTGRES_MAX_POOL_SIZE` | **每个 Deployment Runtime** 对其 Workflow Database 的 pg 连接池上限。Worker 把它注入每个 Deployment（Reserved：Project Secrets 不能覆盖），使 Workflow 实例总负载可规划：`max_connections ≈ pool size × 并发运行的 Deployment 数 + 平台连接池`。非法或非正值回落到默认值。                                                                                                                                                                                                                           | `10`（pg 的隐式连接池默认值） | Worker（`apps/worker/src/jobs/process-support.ts`）、Deployment Runtime（`@evelandhq/workflow-world`）                                                                      |
| `WORKFLOW_WORLD_URL`              | 支撑 `@evelandhq/workflow-world`（平台的多租户 Workflow World）的共享 Postgres 数据库。每个新构建都会烘焙这个 World，因此生产 Worker 缺少该 URL 时启动 Fail Closed。API 从它派生 World 的 Cluster Identity，并拒绝为注册到其他 Cluster 的 Dispatcher 执行 Workflow-step Activation。Deployment Retention 保护带非终态 Run 的 Deployment（被未解决的 Dispatch Dead Letter 隔离的除外）；Worker 启动或 Tenant Provisioning 会在 Dispatcher 或 Deployment 使用之前自动应用全部待执行 Schema Migration。 | —（生产必填）                 | API 与 Worker（`packages/core/src/workflow-world-url.ts`、`packages/db/src/workflow-world-identity.ts`、`apps/worker/src/runtime/workflow-world-bootstrap.ts`）、Dispatcher |
| `WORKFLOW_WORLD_BOOTSTRAP_URL`    | 读取方平台进程自身视角下的同一共享 Workflow Database。当平台访问 Postgres 的主机名与 Deployment 不同（如 Docker Desktop 下的 `host.docker.internal`）时设置。                                                                                                                                                                                                                                                                                                                                        | `WORKFLOW_WORLD_URL`          | API 与 Worker（`packages/core/src/workflow-world-url.ts`）、Dispatcher                                                                                                      |

> **`WORKFLOW_WORLD_URL` 必须指向独立的数据库**，而不是 `DATABASE_URL` 所指的那个
> （惯例是 `eveland` 与 `eveland_workflow`）。Worker 会把这个 DSN 注入每个 Deployment，
> Agent 代码因此持有它；如果它指向平台数据库，账号、会话和加密的项目 Secret 也会一并暴露。
> `eveland-ctl doctor` 会把共用数据库报告为 `workflow-world-database`。

> **Agent 运行在 Docker 中时，`WORKFLOW_WORLD_URL` 必须使用容器可达的主机名**（如
> `host.docker.internal`），不能用 `localhost`，因为 Agent 容器从容器内部访问宿主机
> 数据库。`WORKFLOW_WORLD_BOOTSTRAP_URL` 则可以使用 `localhost` 或 Compose Service
> 名，因为只有平台自己的进程读取它。

## Encryption

| 变量             | 用途                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | 默认值                                        | 读取位置     |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------- | ------------ |
| `APP_SECRET_KEY` | Eveland 所有静态加密数据的根密钥：Project Secret、共享 Agent 环境、个人 Git Host 凭据、外部 Observability Destination、Agent Connection 配置与凭据、Identity Provider client secret、Identity 签名密钥以及 OIDC 登录事务。每种用途用 HKDF-SHA256 按明确的用途派生独立密钥，所有加密值使用同一个带版本的 AES-256-GCM 信封（`sealed:v2:...`）；Agent 遥测签名密钥也以同样方式派生。API 写入时加密；Worker 只在所属 Runtime 边界解密。轮换有意要求重新部署全部 Agent Deployment，使其签名的遥测凭据匹配新的 API 密钥。由 `assertValidAppSecretKey` 校验。 | 仅限开发的 `eveland-dev-secret-key-000000000` | API + Worker |

> **生产环境必须更换 `APP_SECRET_KEY`。** 保留开发默认值意味着存储的 Secret 实际上
> 处于无保护状态。

## Agent-user Identity

| 变量                                   | 用途                                                                                                                                                                                                                                                                                                                                  | 默认值                                                    | 读取位置                                       |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- | ---------------------------------------------- |
| `EVELAND_IDENTITY_ISSUER`              | 嵌入 Eveland Caller Token 的稳定公开 Issuer（覆盖项；默认由 `EVELAND_PUBLIC_ORIGIN` 派生）。必须与每个消费方 Chat 服务和 Agent Verifier 配置的 Issuer 一致。只在需要与公开 Origin 不同的 Issuer 时显式设置——例如存量安装保留旧的 API Origin Issuer。生产环境中它与 `EVELAND_PUBLIC_ORIGIN` 均未设置时**报告为缺失**。启动不会被阻断。 | 派生                                                      | API + Worker                                   |
| `EVELAND_IDENTITY_ALLOWED_ORIGINS`     | 逗号分隔的精确浏览器 Origin，允许读取 Identity Session 状态、请求 Caller Token 与登出。公开 Agent Catalog 不依赖此 Allowlist。不支持通配符。无代码级默认值：未设置时任何浏览器 Origin 都不能使用 Identity API（示例：本地 chat 前端用 `http://localhost:3010`）。                                                                     | 未设置（无 Origin）                                       | API                                            |
| `EVELAND_IDENTITY_JWKS_URL`            | 注入每个 Deployment 的 Agent 可达公钥 URL。它可以使用私有/回环地址，只要 `EVELAND_IDENTITY_ISSUER` 保持稳定公开 Issuer。                                                                                                                                                                                                              | `http://host.docker.internal:17301/.well-known/jwks.json` | Worker                                         |
| `EVELAND_PROJECT_ID`                   | Worker 注入每个 Agent Deployment 的 Audience/Project 绑定。Project 与 Shared Agent Environment 的值不能覆盖它。                                                                                                                                                                                                                       | 当前 Project ID                                           | 部署的 Agent                                   |
| `EVELAND_IDENTITY_OIDC_ALLOW_INSECURE` | 设为 `1` 允许平台 OIDC Identity Provider 访问 `http://` 或私网 Issuer。为对回环 IdP 的本地集成测试而存在；生产环境绝不设置——它会关闭 Identity Broker 每次 OIDC 请求的 HTTPS 与私网地址防护。                                                                                                                                          | 未设置（仅 https Issuer）                                 | API                                            |
| `EVELAND_ALLOWED_REALM_IDS`            | SDK 侧 Realm Allowlist：逗号分隔的 Realm ID（`irlm_...`），限定 Agent 的 `evelandIdentity()` 接受哪些 Realm 的用户。Identity Broker 认证调用者，但不决定哪个 Realm 可以访问哪个 Agent，因此不设置时接受任何已启用 Realm 的 Token；设置后其他 Realm 的 Token 会作为未认证拒绝。显式的 `allowedRealms` 选项优先于它。                   | 未设置（任何已启用 Realm）                                | 部署的 Agent（`packages/eveland/src/auth.ts`） |

`eveland_identity` Cookie 与 Better Auth 分离，作用域为 `/api/identity`；
`/api/agent-catalog` 是公开的、与 Identity 无关的投影。Caller Token 为 ES256、短时效，
把一个 Principal 认证到一个 Project Audience；业务授权仍由 Agent 负责。浏览器返回
Origin 在 System > Identity 中注册；环境的 CORS 配置不会创建或扩大该 Redirect
Allowlist。

即使旧的本地 `.env` 不含这些变量，Native 开发也会提供表中默认值。API 与 Worker 的
开发 Watcher 同时监听共享 `.env`。注入的 Issuer 或 JWKS URL 变化时，Worker 记录一份
配置 Fingerprint，并为每个存活 Deployment 排队一次定向重启，使运行中的 Agent 不会
保留过期的 Verifier 设置。生产环境不提供 localhost Fallback，必须显式配置。

Internal-provider 里程碑使用 Same-site 浏览器拓扑。Eveland Identity 与 Chat Origin
必须共享一个 Schemeful Site（通常为同级 HTTPS 子域），因为 Identity Cookie 是
`SameSite=Lax`。仅有精确 CORS 配置并不能允许来自无关 Site 的携带凭据请求。

## Workflow Dispatcher

Dispatcher（`apps/workflow-dispatcher`，`@evelandhq/workflow-world` 内 Dispatcher 的薄启动器）从共享 Workflow Database Claim Durable Workflow Job，并把每个 Step POST 回所属 Agent Deployment，若其已被 Idle-reaped 则先激活。它读取上文的 `WORKFLOW_WORLD_URL` / `WORKFLOW_WORLD_BOOTSTRAP_URL`，外加下表变量。

## 宿主机工具

由运维或作者 shell 中的 `eveland-ctl` 与 `eveland` CLI 读取，平台进程不读取：

- `EVELAND_HOME` — `eveland-ctl` 管理的 appliance 根目录：Linux 上为 `/opt/eveland`，macOS 上为 `~/.eveland`。`eveland` CLI 也读取它，默认使用该实例的公开 origin。见 [eveland-ctl](/zh/docs/reference/ctl)。
- `EVELAND_TOKEN` — 无交互场景（CI）使用的 CLI Access Token。设置后，`eveland` CLI 用它代替该 origin 下保存的凭据。见 [CLI](/zh/docs/reference/cli)。

## Test-only 变量

只被测试或集成 Harness 读取；不属于运行时配置：

- `EVELAND_POSTGRES_TEST_URL` — Postgres 集成测试。
- PGlite 支撑的测试不需要环境变量；它们对新迁移好的数据库运行生产 SQL Store。
- `EVELAND_VALIDATE_OTEL_COLLECTOR` — 设为 `1` 运行基于 Docker 的 Collector 配置校验测试。
- `E2E_CHECK_MODE` — Agent-sandbox 端到端检查。
- `SMOKE_SECRET` — bwrap / systemd 冒烟测试。
- `EVE_EXAMPLE_MODEL`、`EVE_EXAMPLE_REAL_LLM` — 示例 Agent 测试。
