---

Eveland 遵循**最小权限原则（Principle of Least Privilege）**与**防御性纵深架构**，严格限制能够跨越信任边界的组件与数据通路。

---

## 1. 认证与系统信任边界

| 边界类型                | 适用范围              | 鉴权机制                    | 安全约定                                                     |
| :---------------------- | :-------------------- | :-------------------------- | :----------------------------------------------------------- |
| **平台控制面认证**      | Dashboard 与 API      | Better Auth 会话（邀请制）  | 仅限授权团队成员；控制面登录态绝不会作为凭证注入 Agent。     |
| **公开 Agent 数据面**   | Agent API 与 Web 访问 | Agent 自身定义的认证        | 网关透明转发请求中的 Authorization 与 Cookie，不越权篡改。   |
| **Playground 在线调试** | 控制台在线调试会话    | 临时动态凭证 / Caller Token | 凭证仅在单次调试请求中动态解析，不落库、不写入网关访问日志。 |

---

## 2. 组件权限划分矩阵

- **Agent Gateway**：面向公网的唯一入口，仅负责反向代理与流式传输。不持有 Docker Socket，无宿主机文件系统写权限，无法接触解密后的数据库与密钥。
- **控制面 API**：持有平台状态读写权限，但**无宿主机进程控制权限**，不能直接执行系统命令。
- **宿主机 Worker**：唯一的特权生命周期编排器。以 root 启动但**无任何公网监听端口**。
- **Agent 运行实例**：每个部署均运行在各自独立的临时 systemd `DynamicUser` 下，开启严格的文件系统只读保护与隔离沙箱。

---

## 3. 不受信任代码构建与沙箱隔离

第三方 Agent 源码及其引用的 npm 依赖树被视作潜在不受信任输入：

- **专用非特权构建用户**：依赖安装（`npm ci`/`pnpm install`）与代码打包（`npx eve build`）强制在 `eveland-build` 用户下运行，严禁以 root 身份执行生命周期脚本。
- **bubblewrap 强隔离沙箱**：构建进程只能读写当前 Release 目录与共享 npm 缓存，宿主机核心目录与其它项目数据均被完全遮蔽。
- **环境变量过滤**：Worker 自身的敏感配置（如数据库密码、Master Key）在触发构建前会被严格剥离。

---

## 4. 密钥生命周期与脱敏保护

- **静态加密存储**：所有环境变量密钥均使用 AES-256-GCM 算法加密保存在数据库中，只有目标 Agent 进程启动时才会动态解密。
- **进程级安全注入**：解密后的环境变量仅写入 root 拥有且权限为 `0600` 的临时文件供 systemd 读取，绝不通过命令行参数（argv）或环境变量直接暴露。
- **全链路自动脱敏**：系统在收集运行诊断、异常堆栈与日志输出时，会自动对已知密钥实施掩码脱敏（Masking），杜绝凭据泄漏。

---

## 5. 网络边界与端口防护

- **仅公网暴露 `80` 与 `443`**：反向代理（Traefik）负责统一接入，将请求转发至内网端口 `17300`（Agent Gateway）。
- **内部私有回环保护**：
  - 核心服务 API（`17301`）、控制台（`17302`）、内置 Postgres（`17310`）均仅监听 `127.0.0.1`。
  - Agent 实例动态端口（`18000–18999`）仅供 Gateway 内部反向代理，**严禁在宿主机公网防火墙上对外放行**。
- **排除 `/internal/*` 路径**：反向代理严格屏蔽 `/internal/*` 路由，确保机器间服务认证接口无法从公网触达。
