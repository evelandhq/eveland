在 Eveland 中，**部署定义 (Deployment) 与实际运行的操作系统进程生命周期是完全解耦的**。即使底层进程因无流量而停止，Deployment 的不可变发布包、预览域名、生产路由以及会话绑定均持久保留。

---

## 1. 进程生命周期与按需冷激活 (Scale-to-Zero)

Eveland 通过租约机制（ActivationLease）实现自动扩缩容至零，确保宿主机资源得到充分利用：

```text
外部请求 / 定时调度 / 工作流步骤到达
  → 获取短期激活租约 (ActivationLease)
  → 若实例处于休眠 (stopped)，Worker 毫秒级拉起进程 (Cold Start)
  → 网关转发请求 / 执行任务
  → 任务完成，租约释放
  → 空闲超时 (默认 5 分钟无租约)，Worker 优雅停止进程
```

- **并发合并**：对于同一休眠部署的多个并发入站请求，平台会自动合并为一个拉起任务，避免重复启动。
- **状态保留**：实例休眠仅释放 CPU 与内存占用；下一次请求到达时无缝重新唤醒。

## 2. 部署运行机制与环境安全

| 阶段                  | 执行环境与安全边界                            | 关键动作                                                                                                                                   |
| :-------------------- | :-------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------- |
| **构建 (Build)**      | 非特权 `eveland-build` 用户 + bubblewrap 沙箱 | 在只读受限环境中执行 `npm ci` 和 `npx eve build`。Worker 自身的数据库凭证与主密钥被严格屏蔽，防止第三方依赖脚本越权。                      |
| **运行 (Run)**        | 独立的 systemd `DynamicUser` 瞬态服务         | 绑定本地回环端口（`127.0.0.1:18000–18999`）；开启 `ProtectSystem=strict` 与 `PrivateTmp`；敏感密钥以 root 拥有的只读文件（`0600`）注入。   |
| **健康检查 (Health)** | 本地 HTTP 探测                                | Worker 持续探测 `http://127.0.0.1:<port>/eve/v1/health`。超时未响应时，平台在清理进程前自动抓取最近的 Journal 日志与脱敏错误信息存入诊断。 |
| **休眠 (Idle)**       | 进程停止，元数据保留                          | 释放系统内存；不可变发布产物与会话状态持久保留。                                                                                           |

## 3. 资源配额与限制

通过全局环境变量控制每个 Deployment 的 cgroup 资源边界：

```ini
# 单个 Agent 进程内存上限（防止内存泄漏打垮宿主机）
EVELAND_MEMORY_MAX=512M

# 单个 Agent 进程 CPU 配额（例如 100% 对应单核）
EVELAND_CPU_QUOTA=100%

# 最大并发任务/线程数
EVELAND_TASKS_MAX=1024

# 单条沙箱命令最长执行超时时间（毫秒，默认 10 分钟）
EVELAND_SANDBOX_RUN_TIMEOUT_MS=600000
```

_合理的配额规划请查阅[容量规划](/zh/docs/operations/capacity)。_

## 4. 沙箱注入与持久化工作区

Eve 项目内置的代码执行与文件操作工具（`bash`、`read_file`、`write_file` 等）由平台自动注入的 `@evelandhq/sandbox-bwrap` 驱动：

- **无缝兼容**：平台在发布包中原地包装沙箱后端，同时完整保留开发者在代码中定义的 `bootstrap()`、`onSession()` 及工作区初始模板（`agent/sandbox/workspace/**`）。
- **会话工作区隔离**：每个长效会话（Session）独享专属的 `/workspace` 目录。在部署重启、重新发布或冷激活时，同一会话的工作区文件均保持持久存在，不会丢失。

## 5. 共享工作流引擎 (Shared Workflow World)

持久化工作流负责在 Agent 进程休眠后，仍能准确触发未来的定时器或异步回调：

- **单例外置调度**：全集群必须且仅运行一个 [Workflow Dispatcher](/zh/docs/production/workflow-dispatcher)，通过 PostgreSQL Advisory Lock 保证互斥。
- **租户强隔离**：全平台 Agent 共享同一个持久化工作流数据库（由 `EVELAND_WORKFLOW_WORLD_URL` 指定），底层数据模型按 `tenant_id`（即项目 ID）逻辑分区。
- **引擎注入**：平台在发布准备阶段自动注入 `@evelandhq/workflow-world@0.14.0`（替代旧版 `@workflow/world-postgres@5.0.0-beta.34`），确保执行状态统一由外置调度器接管。
- **自动迁移**：Worker 启动及新项目创建时，会自动应用待执行的工作流架构迁移。

### 工作流保留策略 (Retention Classes)

| 触发源类型                            | 默认保留级别  | 清理策略与数据保留期限                                              |
| :------------------------------------ | :------------ | :------------------------------------------------------------------ |
| **定时调度 (Schedules)**              | `scheduled`   | 执行完成后 1 分钟压缩；成功保留 24 小时，失败保留 7 天后自动归档。  |
| **交互请求 (Playground / HTTP API)**  | `interactive` | 默认交互类。成功保留 24 小时，失败保留 7 天，执行历史图保留 30 天。 |
| **关键持久任务 (Durable Operations)** | `persistent`  | 业务标记的关键任务，系统永不自动清理。                              |

## 6. 进程对账与孤儿回收 (Reconciliation & Sweep)

Worker 运行后台巡检任务，确保宿主机实际进程与平台数据库状态保持一致：

- **失管进程接管**：如果发现属于合法运行中部署但未被生命周期纳管的进程，Worker 会将其自动纳入空闲回收生命周期。
- **孤儿进程清理**：对于已被删除、归档或状态异常的旧部署进程，Worker 在宽限期后会自动调用 systemd 强制停止，防止端口泄露与资源浪费。
- **端口冲突校验**：在分配端口前，平台严格核查端口监听归属，杜绝进程串号风险。

## 7. 项目删除流程

当调用 `DELETE /projects/:projectId` 时，平台执行安全删除流水线：

1. 项目状态变更为 `deleting`，拒绝后续变更请求；
2. 优雅停止该项目名下所有运行中的 Deployment 进程；
3. 清理平台数据目录下该项目的构建目录、发布产物及沙箱缓存；
4. 清理共享工作流数据库中属于该租户的数据分区；
5. 最后删除数据库控制面记录。若中途任何步骤异常，支持安全重试。
